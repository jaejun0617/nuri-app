# 6차 v1.0 기준선 기획서

작성일: 2026-05-06

## 1. 문서 목적

이 문서는 v1.0에 실제로 포함된 기능과 닫힌 task를 고정한다. “지금 앱이 어디까지 완성됐는지”를 기준선으로 남기며, 스토어 제출 완료 상태로 오해하지 않는다.

## 2. v1.0 제품 성격

v1.0은 기능 개발 Code Freeze 기준선이다. 기존 기능을 안정화하고 현재 사용자 화면과 서버 계약을 고정하는 버전이며, 운영자 QA와 스토어 제출 자산까지 모두 끝난 제출 완료 버전은 아니다.

## 3. v1.0 포함 기능

- 이메일/비밀번호 로그인, 회원가입, 비밀번호 재설정
- Google/Kakao/Naver social login app-side entrypoint
- 닉네임 설정과 기존 onboarding boot contract
- 커뮤니티 최소 운영 방어선
- 건강관리 Phase 1 baseline
- 우리동네 동물병원 유저 서비스 기준 closeout
- 날씨 API 비용 방어와 `weather-cache` 경로
- 계정 탈퇴 7일 유예와 자동 파기 worker 계약

## 4. v1.0 제외 기능

- Apple social login
- Entitlement / billing foundation
- Premium AI reply
- Guestbook private letters 확장
- Typography foundation rollout
- 실제 결제/과금 구조

## 5. Auth / Social Login 상태

- Google/Kakao/Naver social login은 app-side 마감 상태다.
- Google/Kakao는 Supabase built-in provider, Naver는 Supabase custom OAuth provider id `custom:naver`를 사용한다.
- `nuri://auth/callback`은 OAuth callback, `nuri://auth/reset`은 password reset recovery로 분리되어 있다.
- social login 버튼 하단에는 이용약관/개인정보처리방침 확인 및 동의 간주 고지 UI가 추가됐다.
- Apple social login은 Android-first v1.0 범위에서 제외한다.
- provider console 설정과 OAuth success smoke는 v1.1 착수 전 v1.0 잔여 task/risk closeout에서 운영 확인으로 다룬다.

## 6. Supabase DB 상태

- Supabase DB migration release gate는 closed다.
- remote apply는 no-op이다.
- local/remote migration은 `20260429130000`까지 일치한다.
- pending migration은 없다.
- post-apply db lint error는 0건이다.
- 기존 warning 1건은 `delete_my_account` 관련 기존 warning으로 분리 기록됐다.
- `db diff --linked`는 CLI/Docker/temp role auth blocker로 evidence 분리됐고, DB schema apply blocker는 없다.

## 7. 커뮤니티 상태

커뮤니티는 write-path rate limit, dedupe, blocked-term, stable error contract, 신고/auto-hide, moderation queue/action log, image cleanup pending 계약을 가진다. moderation 없는 기능 확장은 v1.0에서 열지 않는다.

## 8. 건강관리 상태

건강관리 Phase 1 baseline은 repo 구현, linked remote migration, row-level 검증, Android 실기기 핵심 QA가 완료된 상태다. 고급 인사이트와 premium 연결은 v1.1 후보로 분리한다.

## 9. 동물병원 상태

우리동네 동물병원은 유저 서비스 기준 closeout 상태다. public search RPC, 리스트/상세, 전화/길찾기 CTA, weather/place 관련 provider cost defense와 trust gate를 유지한다. 운영자 검수 UI 실계정 QA는 v1.1 착수 전 v1.0 잔여 task/risk closeout으로 분리한다.

## 10. 날씨/API 비용 방어 상태

날씨 클라이언트는 Open-Meteo를 직접 호출하지 않고 Supabase Edge Function `weather-cache`만 호출한다. `public.nuri_weather_cache` remote apply와 Edge Function deploy, Android 실기기 홈/상세 QA, direct Open-Meteo call 0건 검증까지 완료됐다.

## 11. 계정 탈퇴/정책/신뢰성 상태

정책 문서 public 연결, 계정 삭제 안내, 비밀번호 재설정, 계정 탈퇴 7일 유예, 자동 파기 worker 계약은 v1.0 기준선에 포함한다. 구현 완료와 운영 증적은 문서에서 분리 관리한다.

## 12. Code Freeze 이후 금지 사항

- 신규 기능 구현 금지
- DB schema/migration 임의 변경 금지
- Auth/social login 구조 확장 금지
- Entitlement/billing, Premium AI, private letters 확장, typography rollout 착수 금지
- Apple social login 구현 금지

## 13. v1.0 기준선 판정

v1.0 기능 개발 기준선은 고정 완료다. 다만 v1.1 업데이트로 넘어가기 전 운영자 QA, 실기기 최종 스모크, Google/Kakao/Naver OAuth 성공 smoke, 앱 스토어 출시 자산, 최종 제출용 RC 빌드, clean artifact evidence, release risk ledger 전수 정리를 v1.0 마감 gate로 먼저 닫는다.
