# 6차 v1.1 업데이트 기획서

작성일: 2026-05-06

## 2026-07-14 현재 기준 보정

v1.1 업데이트 후보 중 이미 구현·검증된 항목은 현재 미완료로 재계산하지 않는다. 관리자 홈페이지 단계별 본구현은 종료했고, 남은 custom domain/외부 monitoring/MFA material/상시 2인 운영 체계는 외부 운영 조건으로 분리한다.

현재 별도 PO 승인 전에는 앱 전체 디자인/폰트 리뉴얼, Play Store 자산, 실제 push provider 활성화, 자체 전국 POI runtime 전환, Naver 복구, Apple 추가를 진행하지 않는다.

## 1. 문서 목적

이 문서는 v1.1 신규 업데이트 후보와 우선순위를 정리한다. v1.1은 v1.0 미완성 수습이 아니라 기능 확장과 상품화 준비 트랙이지만, v1.0 잔여 task와 release risk closeout 이후에 착수한다.

## 2. v1.1 제품 성격

v1.1은 v1.0 기능 기준선과 잔여 risk closeout 위에서 확장 기능, 상품화, 운영 고도화를 검토하는 업데이트 트랙이다. 실제 결제 오픈 여부와 AI 답장 상품화는 별도 PO 결정이 필요하다.

## 3. v1.1 업데이트 원칙

- 기존 v1.0 기준선을 흔드는 대규모 구조 변경을 피한다.
- 사용자 데이터, 공개 trust, 결제, AI는 정책/로그/운영 방어선과 함께 연다.
- 기능 확장은 운영자 QA, 보안, 개인정보, 비용 통제와 함께 판단한다.

## 4. 우선순위 후보

2026-06-04 V1.0 closeout 이후 추천 우선순위는 `docs/project-memory/v1.1-roadmap-briefing-2026-06-04.md`를 따른다.

1. 산책/location discovery 자체 POI DB + Supabase PostGIS 전환 설계 PR
2. Kakao Local 사용자 runtime 제거 전략
3. provider admin batch import dry-run contract
4. 운영자/admin P2 evidence 및 audit 고도화
5. Guestbook private letters 확장
6. Entitlement / billing foundation
7. Premium AI reply 선행조건
8. MapLibre / PMTiles / 자체 지도 스택 후보 검토
9. Typography foundation 제한 적용 판단
10. Naver OAuth cleanup

## 5. Apple social login

Apple social login은 Android-first v1.0에서 제외했다. iOS 출시 시점에 Sign in with Apple 정책, 다른 social login 제공 여부, App Store 심사 기준을 함께 검토한다.

## 6. Entitlement / billing foundation

`user_subscriptions`, `user_entitlements`, billing event contract는 v1.1 신규 업데이트 후보로 관리한다. 실제 결제 오픈은 별도 PO 결정과 스토어 정책 검토 후 진행한다.

## 7. Premium AI reply

Premium AI reply는 notice, consent, generation log, provider policy를 선행조건으로 둔다. AI 답장은 편지/추모 맥락에서 민감도가 높으므로 사용자의 명시 동의, 생성 기록, 실패/취소 UX, provider 정책이 먼저 필요하다.

## 8. Guestbook private letters 확장

v1.0은 기존 단순 방명록 상태로 유지한다. v1.1에서는 private letters 상세/수정/삭제, AI reply 연동, 확장 IA를 기존 Guestbook과 분리된 확장 기능으로 다룬다.

## 9. Typography foundation rollout

Typography foundation은 전면 리디자인이 아니라 제한 화면군부터 적용 여부를 판단한다. AppText/token 적용은 회귀 위험이 있으므로 화면군, 검증 범위, 접근성 기준을 먼저 고정한다.

## 10. 운영자/admin 고도화

동물병원 운영자 검수 UI 실계정 QA, moderation/admin UI, action log evidence, 운영자 권한 경계는 v1.1 운영 고도화 후보로 관리한다.

## 11. 외부 API 키 통제/환경 분리/운영 도구

Open-Meteo customer API key/계약, provider key 분리, no-JWT endpoint abuse throttle, 환경별 secret 운영 도구를 v1.1 기술 부채로 정리한다.

## 12. 건강관리 후속 정리

건강관리 메뉴 전환, 타임라인 건강 입력 제거 후속 확인, 생활 병원/약 이관 안정화, premium 인사이트 연결은 v1.1 후보로 둔다.

## 13. 동물병원/장소/지도 고도화

place enrichment stale cache refresh, provider coverage 확대, native Google Maps preview 복원, 장소/동물병원 `confirmed` 개방 검토는 public trust gate를 유지하는 범위에서 판단한다.

## 14. v1.1 착수 전 v1.0 마감 Gate

2026-06-04 기준 V1.0 P0/P1은 0건이고 V1.0 필수 잔여는 없다. 아래 gate는 닫힌 상태로 유지하며 새 blocker 증거가 없으면 재오픈하지 않는다.

- Google/Kakao/Naver provider console 설정 확인과 OAuth 성공 smoke
- 운영자 QA / 실기기 최종 스모크
- 최종 제출용 RC 빌드 확정
- clean artifact evidence 고정
- release risk ledger 전수 정리와 남은 P0/P1/P2 재분류

Play Store 제출 자산은 V1.0 기능/QA blocker가 아니며, NURI 앱 개발과 QA가 완전히 끝난 뒤 최종 제출 직전 준비 단계에서 진행한다. 이 항목은 V1.1 신규 업데이트 작업에도 포함하지 않는다.

## 15. 다음 액션

V1.1 1순위 마일스톤인 산책/location discovery 자체 POI DB + Supabase PostGIS 전환 설계 PR을 착수한다.
