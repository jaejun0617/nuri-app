# 현재 프로젝트 상태

## 현재 목표

NURI의 현재 목표는 `핵심 task 구현 완료`다.

현재 판단 기준은 아래 3개다.

- 현재 우선 Task가 코드와 linked remote에 실제 계약으로 반영되어 있는가
- 새 도메인 전환과 기존 핵심 흐름이 서로 충돌하지 않는가
- release 문서는 유지하되, 지금 당장 닫아야 하는 lane과 후행 출시 lane이 분리되어 있는가

## 운영 기준으로 닫힌 항목

- 회원가입의 `이용약관`, `개인정보처리방침`, More의 `계정 삭제 안내`는 실제 public 문서로 연결됐다.

- `docs/policies/` 최신본은 Notion 공개본과 동기화된 상태로 관리한다.

### 비밀번호 재설정

- `PasswordResetRequest -> recovery link -> PasswordResetForm -> SignIn 복귀` 흐름이 구현됐다.
- Android 실기기 기준 recovery 링크 복귀, 비밀번호 변경 성공, `SignIn` 복귀까지 검증됐다.
- 기존 계정 컨텍스트로 새는 blocker는 닫혔다.

### 계정 탈퇴 7일 유예

- 탈퇴는 즉시 하드 삭제가 아니라 `요청 -> 7일 유예 -> 복구 가능 -> 자동 최종 삭제` 구조로 재편됐다.
- 유예기간 로그인 차단과 복구 모달이 앱에 반영됐다.
- 자동 파기 worker는 remote에 실제 배포됐고, `pg_cron -> Edge Function -> finalizer -> storage cleanup` 구조가 잠겼다.
- time-travel E2E 기준 due request 1건이 실제 `completed`까지 수렴했고, `profiles / pets / auth.users` 잔존 row `0`을 확인했다.

### 커뮤니티 최소 운영 방어선

- 게시글/댓글 write-path는 rate limit, dedupe, blocked-term, stable error contract를 가진다.
- 신고는 self-report 차단, duplicate 차단, reporter flag trace, unique reporter 기준 auto-hide, moderation queue/action log까지 갖는다.
- `community_image_assets`와 cleanup pending 계약이 존재하고, hidden 이미지 비노출까지 remote 재검증이 끝났다.
- `comment auto-hide`, `reporter flag trace`, `image upload/image_assets`, hidden 이미지 비노출 blocker는 닫혔다.

### 커뮤니티 인앱 정책 고지

- 목록 상단 notice, 글쓰기 helper box, 정책 링크 팝업이 반영됐다.
- Android 실기기 기준 정책 팝업과 앱 복귀를 PO가 확인했다.

### 닉네임 정책과 기본 레이아웃

- 닉네임 계약은 앱/remote 기준 `2..10`으로 정렬됐다.
- Community header, Timeline 하단 탭 유지, Android bottom gap 보정까지 실기기 검증이 끝났다.

### 장소/동물병원 Trust Layer 기본 계약

- 공개 라벨은 `후보 / 확인 필요 / 검수 반영` 3개로 잠겼다.
- personal state와 public trust는 분리 유지한다.
- `confirmed`는 계속 닫혀 있다.
- candidate/trust/user layer 경계는 코드와 문서에서 일치한다.
- `반려동물과 여행`은 앱 런타임에서 제거됐고, remote migration 이력은 과거 운영 히스토리로만 남긴다.

### 날씨 도메인 비용 방어 closeout

- repo 기준 `weather-cache` Supabase Edge Function과 `public.nuri_weather_cache` migration이 추가됐다.
- 기존 구조는 앱 클라이언트가 Open-Meteo forecast와 air-quality endpoint를 직접 호출하고, React Query 2분 stale / zustand·AsyncStorage 3분 preview / focus 60초 refresh를 사용했다.
- 변경 구조는 클라이언트가 `weather-cache`만 호출하고, Edge Function이 0.02도 좌표 bucket으로 forecast + air quality bundle을 조회/캐시한다.
- 서버 TTL은 fresh 60분, provider 장애 시 stale fallback 6시간이다. 클라이언트 TTL은 React Query stale/focus 55분, gc 2시간, preview 60분으로 조정됐다.
- Open-Meteo attribution은 홈 날씨 카드와 날씨 상세 하단에 `날씨 데이터: Open-Meteo`로 반영됐다.
- API key/customer endpoint는 `OPEN_METEO_BASE_URL`, `OPEN_METEO_AIR_QUALITY_BASE_URL`, `OPEN_METEO_API_KEY`, `OPEN_METEO_PROVIDER_MODE` 환경변수로만 처리한다.
- linked remote에 `20260429130000_weather_cache_proxy.sql`이 적용됐고, `public.nuri_weather_cache` table은 RLS enabled, public policy 0개, `service_role` 경유 구조로 확인됐다.
- `weather-cache` Edge Function은 `--no-verify-jwt`로 재배포되어 `ACTIVE` v2 상태다. 수동 smoke 기준 1차 `source=provider`, 2차 `source=fresh_cache`, attribution과 `expiresAt`/`staleUntil` contract가 확인됐다.
- Android 실기기 `SM_S937N` 기준 홈 날씨 카드, 날씨 상세, `날씨 데이터: Open-Meteo` attribution, logcat `weather-cache completed source=fresh_cache`, Open-Meteo direct call 0건을 확인했다.
- 현재 완성도는 96%로 판정한다.
- Open-Meteo customer API key/계약 확인과 `weather-cache` public endpoint abuse throttle/rate limit은 v1.0 blocker는 아니나 운영 고도화 항목이며, v1.1 기술 부채로 이관한다.

## 지금 당장 우선할 핵심 항목

### 1. social login provider 설정 대기

- Google/Kakao app-side OAuth entrypoint와 `nuri://auth/callback`은 구현됐다.
- Supabase Google/Kakao provider는 disabled 상태라 v1.0 사용자 화면 버튼은 readiness gate 뒤로 숨긴다.
- Google/Kakao는 `CONFIG_WAITING`, Naver는 `BLOCKED_BY_UNSAFE_IMPLEMENTATION`, Apple은 Android-first v1.0 제외로 판정한다.
- PO가 provider console, Supabase provider, redirect allow-list를 설정한 뒤 Android OAuth 성공 smoke를 수행해야 social 버튼을 다시 노출할 수 있다.

### 2. Guestbook -> private letters 실기기/remote 확인

- repo 기준 2026-04-23에 GuestbookTab은 사용자 표시명 `편지함`으로 바뀌었고, 화면은 선택 펫 기준 private letters 작성/조회 UI로 1차 전환됐다.
- route 이름 `GuestbookTab`은 기존 복귀 흐름을 깨지 않기 위해 유지한다.
- `letters` legacy table은 공개 방명록이 아니라 RLS 안의 user-authored private letter로만 사용한다.
- 게스트는 로그인 유도, 펫이 없는 로그인 사용자는 펫 등록 CTA를 본다.
- AI 답장, 공유, 신고, 공개 댓글은 아직 열지 않았다.
- Android 실기기 편지 작성/목록 반영 smoke와 linked remote `letters` catalog/RLS 재확인은 남아 있다.

### 3. entitlement / billing foundation

- Premium AI, 멀티펫 구독, 향후 paywall은 entitlement 없이 열면 안 된다.
- `user_subscriptions`, `user_entitlements`, billing event contract를 먼저 정리한다.

### 4. Premium AI reply 선행조건 정리

- AI 답장 기능은 letters IA, entitlement, consent, generation log, provider policy가 먼저 닫혀야 한다.

### 5. typography foundation rollout 여부 판단
