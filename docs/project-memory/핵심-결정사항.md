## 공용 place enrichment 엔진

- 앱은 화면 렌더링 직후 Supabase Edge Function `place-enrichment-demand`를 비동기로 호출할 수 있지만, V1.0 production runtime에서는 hard cap 0 safe no-op을 기본값으로 둔다.

- Google Places 신규 호출은 명시적으로 양수 hard cap을 둔 환경에서만 `claim_nuri_place_enrichment_budget` RPC의 월 하드캡 안에서 허용한다. hard cap 미설정 또는 `0`이면 demand와 worker는 provider fetch와 provider cache overlay 없이 existing/canonical 값으로 safe skip한다.
- 동일 place key에 대한 동시 demand는 `nuri_place_enrichment_jobs` claim/complete 계약으로 병합한다. 여러 사용자가 동시에 같은 장소를 요청해도 provider 호출은 1회만 허용한다.

- Task 9 산책 seed는 `location-discovery-seed` Edge Function에서 Kakao Local을 호출한다. 앱 클라이언트는 Kakao REST API를 직접 호출하지 않으며, 동일 seed 요청은 클라이언트 캐시와 Edge Function URL 캐시로 반복 호출을 줄인다.
- V1.1 이후에만 provider admin batch import, stale cache refresh, MapLibre/PMTiles/자체 POI/PostGIS 구조를 검토한다.

## 날씨 provider cache

- 날씨 클라이언트는 Open-Meteo forecast/air-quality endpoint를 직접 호출하지 않는다.
- 앱은 Supabase Edge Function `weather-cache`만 호출하고, provider 호출/API key/customer endpoint 선택은 서버에서만 처리한다.
- weather cache source of truth는 `public.nuri_weather_cache`이며 앱 클라이언트 직접 select/insert/update policy는 열지 않는다.
- cache key는 raw latitude/longitude가 아니라 0.02도 좌표 bucket과 `locale|timezone` 조합이다. 원본 정밀 좌표와 user id를 함께 저장하지 않는다.
- forecast와 air quality는 한 bundle로 묶어 fresh 60분 TTL을 적용한다.
- provider 실패 시 `stale_until` 6시간 안의 stale bundle을 `stale_cache`로 반환하고, stale cache가 없으면 stable error code를 반환한다.
- Open-Meteo Free/Open endpoint는 production commercial path로 고정하지 않는다. customer API 사용 시 `OPEN_METEO_*` 환경변수와 Supabase secret만 사용한다.
- Open-Meteo attribution은 provider/cache 계약과 날씨 상세에서는 유지한다. 2026-07-11 PO 요청 기준 로그인 홈 compact 날씨 카드에서는 `날씨 데이터: Open-Meteo` 문구를 숨겨 홈 밀도를 낮춘다.
- 2026-04-30 기준 `nuri_weather_cache` remote apply, `weather-cache --no-verify-jwt` deploy, 수동 smoke, Android `SM_S937N` 홈/상세 QA, logcat direct Open-Meteo 0건 검증까지 완료되어 v1.0 날씨 도메인은 close한다.
- Open-Meteo customer API key/계약 전환과 public no-JWT endpoint abuse throttle은 v1.1 운영 부채로 관리한다.
