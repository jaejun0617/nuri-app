## v1.0 Auth / Social Login Scope

- Google/Kakao social login은 v1.0 public provider로 고정한다. Naver는 app-side 구현을 유지하되 V1.0 public surface에서는 soft disable한다.
- Google/Kakao는 Supabase built-in provider, Naver는 Supabase custom OAuth provider id `custom:naver`를 사용한다.
- 2026-05-11 Supabase Dashboard 기준 Google/Kakao는 disabled, Naver `custom:naver`는 Enabled다.
- Google OAuth는 기존 테스트 Google 계정과 `My First Project`를 사용하지 않는다. `My First Project`는 Places API 비용 리스크 프로젝트로 격리하며, NURI OAuth는 새 NURI Google 계정의 OAuth-only project 기준으로 진행한다.
- provider credential 발급/입력과 readiness true 전환은 Google/Kakao만 V1.0 사용 범위로 반영한다. Google/Kakao OAuth success smoke는 Codex Android evidence로 닫혔다. Naver 성공 session smoke는 더 이상 V1.0 blocker가 아니며 V1.1 또는 출시 후 재검토한다.
- provider console setup guide와 로그인 보안/API 방어 기준은 `docs/auth/social-provider-console-setup-guide.md`로 고정했다.
- provider activation-ready flag 기본값은 Google/Kakao `true`, Naver `false`다. Naver는 env가 잘못 켜져도 V1.0 public-surface guard에서 닫힌다.

## 왜 이 순서인가

- v1.0은 더 이상 신규 기능을 늘리지 않는 Code Freeze 기준선으로 닫혔다.
- Supabase DB migration apply gate는 pending migration 0개/no-op apply로 닫혔다.
- Google/Kakao social login은 Android success smoke까지 닫혔고, Naver는 V1.0 public surface에서 soft disable한다. OAuth는 더 이상 V1.0 P1 잔여가 아니다.
- 과금, Premium AI, private letters 확장, typography rollout은 v1.0 완성도를 흔드는 신규 기능이므로 v1.1 업데이트 후보로 분리한다.
- MapLibre/PMTiles/자체 POI/PostGIS는 출시 직전 지도 비용 방어가 아니라 V1.1 구조 고도화이므로 V1.0에서는 provider runtime 차단만 닫는다.
- release APK artifact/provenance와 exact release install smoke는 고정됐다. Play Store 제출 자산은 V1.1 착수 전 gate가 아니라 전체 개발/QA 종료 후 최종 제출 직전 준비로 분리한다.
- 무한루프 방지를 위해 이미 close된 도메인 재조사, app-side social login 재구현, clean artifact 전 RC smoke 반복은 금지한다.
