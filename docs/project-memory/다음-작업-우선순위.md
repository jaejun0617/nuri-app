이 문서는 **현재 승인 범위와 유일한 실행 대기열**을 소유한다. 2026-11-11 운영지침 개편 PO 지시 기준이다. [현재 상태](현재-프로젝트-상태.md#current-baseline)의 제품·수락과 [단일 원장](../qa/nuri-integrated-closeout-2026-10-25.md)을 재사용한다. 문서에 작업이 있다는 사실은 새 실행 승인이 아니다.

**11/14 최신 재개점:** [문의 글 등록·독립 worker 결과](최근-작업-로그.md#nuri-15-registration-independent-worker)를 재사용한다. 독립 로컬 worker와 공용 알림 UI를 통한 문의 진입·읽음·Back은 Metro 개발 범위에서 확인했다. **다음 한 단위는 격리 환경의 문의 답변 target을 운영 공용 알림 계약과 대조해 정식 resolver·목록 통합 범위를 확정하는 것**이다. 현재 DEV 별도 진입을 운영 공용 원장 통합 완료로 보고하지 않는다. 운영 배포·권한 부여·OS push는 별도이며 이미 확인한 등록·읽음·Back을 무조건 반복하지 않는다. 공통 글라스·누리 CTA를 재사용한다. 새 native build는 직전 25 GiB 실측이 필요하다. 아래 11/13 재개점은 이전 이력이다.

**11/13 최신 재개점:** [1~5 후속 근거](최근-작업-로그.md#nuri-15-five-step-closeout)의 탈퇴 사진 정리, 문의 인계·상태 전이, 공지 조회 세대, 답변 durable 전달 검증은 재사용한다. **다음 한 단위는 격리 환경에서 문의 답변 worker의 독립 실행과 공용 알림함 연결을 마감하는 것**이다. 현재는 DEV 전용 인박스 조회 때 로컬 전달기가 worker를 호출하며 독립 배포·Realtime·운영 공용 인박스 완료가 아니다. 현재 화면의 15초 재조회와 즉시 Realtime을 구분한다. 운영 결정표 확정과 새 Metro OFF/Release 수락은 별도이며 25 GiB 미만에서는 native build를 시작하지 않는다. 아래 이전 재개점은 해당 시점의 이력이다. E → C → D와 기존 보류를 유지하며 자동 착수하지 않는다.

**11/13 관리자·문의 후속 재개점:** 로컬 API에서 공지 등록·수정·삭제, 신고 검토, 같은 문의 답변·문의자 전용 알림을 확인했다. 다음 한 단위는 격리 Android의 관리자 공지·신고·답변과 일반 사용자 알림 진입을 앱에서 실제 이어서 확인하는 것이다. 운영 권한 매핑·공용 알림함 연결·공개는 별도이며 E → C → D와 기존 보류를 유지한다.

**11/13 후속 우선:** 아래의 '격리 Auth·게시판 API 앱 연결'은 이번 실제 작성·게시·목록·상세·읽음·Back으로 Metro 개발 범위에서 확인했다. 다음 한 작업은 **전체메뉴·커뮤니티 공지의 관리자 등록·수정·삭제 권한과 앱 경로 연결**이다. 일반 사용자 UI 비노출과 서버 직접 요청 차단을 함께 유지한다. 지정 운영 관리자 계정의 실제 capability는 이번에 조회/부여하지 않았으며 이메일로 대체하지 않는다. 기존 격리 합성 계정/이번 공지를 재사용하고 삭제는 감사 보존·게시 중단과 구분한 계약부터 확인한다. [현재 실행 근거와 한계](최근-작업-로그.md#2026-11-13-nuri-15-격리-공지-앱-연결). 아래 이전 재개 문장은 이 후속으로 대체한다.

**2026-11-13 PO 변경: 공지사항·고객센터(E) → 튜토리얼(C) → 반응형 글꼴 제한 시범(D).** E의 사용자·관리자 로컬 화면, 전체메뉴와 같은 배경·글라스, 잠정 가격·CTA를 준비했다. 새 로컬 격리 환경 재구성도 승인받아 Auth/API/DB와 게시판·텍스트 문의 계약을 검증했다. 다음 한 작업은 **운영 앱 세션과 분리한 정상 격리 Auth 진입 및 실제 게시판 API의 앱 화면 연결**이다. `~/.codex/n15-local`의 세 합성 계정과 공지·문의 자료를 재사용하며 이미 확인한 서버 검사 전체를 반복하지 않는다. 이후 문의 목록·첨부·답변·알림 worker·FAQ 서버와 앱 검증을 이어간다. 현재 화면 예시를 서버 기능 완료로 표시하지 않는다. 로컬 모의 구독은 실제 결제로 승격하지 않으며 실결제는 별도 상품·스토어 계약 이후다. E 다음 C·D 순서를 유지하고 자동 착수하지 않는다. 기존 U1·NAV-01·C0 잔여와 두 U2 보류·C0 미동결·STORE HOLD를 유지한다.

기존 `news.direct`·공지 7종·`pet.together_anniversary`·`pet.memorial`의 격리 앱 증거와 전체 삭제 확인·확정 PASS는 영향이 없으면 재사용한다. 네트워크 실패 복구와 정상 삭제 성공을 다른 조건으로 다룬다. 기존 Google/Kakao 보존 알림함은 전체 삭제하지 않는다. 제품·server·runtime 입력 불변이면 재빌드하지 않는다.

한 번 승인된 후속 U2→U1→NAV→C0 연속 범위에서는 단건마다 재승인을 요청하지 않는다. 이번 문서 작업의 종료 경계를 과거 연속 승인으로 넘어가지 않으며 [계속/중단](../engineering/advanced-codex-workflow.md#continue-stop)을 따른다.

## 미승인 후속 제안

신규 5종 기획은 리서치의 기존 통합 구현순서 제안 상태이며 제품 구현은 시작하지 않았다. 원래 번호는 7 산책 장애, 8 산책 정확도, 9 전체 화면 회귀, 10 최종 보안, 11 정책·법무, 12 최종 RC, 13 Store 자료, 14 베타·Store 각각 PO Go/No-Go로 유지한다. 현재 제품 잔여·승인 범위 확정·각 선행 조건 이후에만 배치한다. 이 표 밖의 새 작업이나 문서 정리 차수를 자동 생성하지 않는다.

새 필수 분모나 자동 실행 목록이 아니다. QA-PHOTO 부재 원인·시점, 과거 QA 일정/댓글/사진 ID별 정리, Google 브랜드 노출/게시, Log Ingestion 이후 관측, 과거 SEC-011과 후속 보안 동결의 세부 적용성은 이번에 재감사하지 않았다. 각각 기존 영수증·소유 ID·해당 도메인 후속 근거가 필요하다. 임의 재생성·전체 삭제·운영 조회·보안 PASS 승격을 하지 않는다.
