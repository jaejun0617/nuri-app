# 다음 작업 우선순위

## 지금 당장 할 것

### 1. 우리동네 동물병원 foundation

- 이유
  - 현재 구조에서 가장 많은 재사용 이득을 얻을 수 있는 신규 도메인이다.
  - 지도, 현재 위치, 리스트, 상세, 외부 지도 전환 구조가 이미 있어 별도 foundation을 세우기 좋다.
  - 여행 도메인을 장기 핵심축으로 키우는 대신 병원 도메인으로 교체하는 방향이 현재 제품 우선순위와 맞다.
- 선행 조건
  - 기존 위치/지도 stack 유지
  - 병원 전용 데이터 계약
  - 후보/신뢰도 문구 기준

### 2. Guestbook -> private letters 전환

- 이유
  - Guestbook은 탭을 차지하고 있지만 실제 기능 도메인이 아니다.
  - 공개형 확장은 금지 방향이므로, placeholder를 유지하는 것보다 private letters IA로 전환하는 것이 맞다.
  - 이후 Premium AI reply 구조도 이 전환을 선행조건으로 가진다.
- 선행 조건
  - selected pet 기반 구조 유지
  - letters domain 계약 재정의

### 3. typography foundation rollout

- 이유
  - AppText와 typography token은 있지만 실제 화면 소비가 분산돼 있어 전체 밀도와 브랜드 톤이 흔들린다.
  - foundation만 두고 미루면 이후 새 도메인 화면도 다시 raw text로 늘어날 가능성이 높다.
- 선행 조건
  - preset 재정의
  - 화면군 rollout 순서

### 4. social login 계약 정리

- 이유
  - 버튼은 이미 노출돼 있지만 실제 provider, callback, native 설정은 비어 있다.
  - 추후 로그인 진입 전환율을 올리려면 `Google first`, `Apple iOS 동시`, `Kakao 후행` 원칙을 먼저 확정해야 한다.
- 선행 조건
  - Supabase provider enablement
  - deep link / callback contract

### 5. entitlement / billing foundation

- 이유
  - Premium AI, 멀티펫 구독, 향후 paywall은 entitlement 없이 열면 안 된다.
  - 현재 문서 권장 구조와 remote 실제 구조가 불일치하므로 foundation을 먼저 맞춰야 한다.
- 선행 조건
  - `user_subscriptions`
  - `user_entitlements`
  - billing event contract

### 6. Premium AI reply 선행조건 정리

- 이유
  - 이 기능은 핵심 BM 후보지만, letters IA, entitlement, consent, generation log, provider policy가 먼저 닫혀야 한다.
  - AI 자체 구현보다 grounded personalization과 안전 규칙을 먼저 고정해야 한다.
- 선행 조건
  - private letters 구조
  - entitlement
  - AI notice / consent

## 왜 이 순서인가

- 지금은 출시가 아니라 구현 완성도가 먼저다.
- release lane은 삭제하지 않되, 모든 핵심 task가 닫힌 뒤 마지막 게이트로 미룬다.
- 먼저 해야 하는 것은 제품 구조를 실제 방향인 `병원 / private letters / entitlement / social auth / Premium AI 선행조건`으로 옮기는 일이다.
