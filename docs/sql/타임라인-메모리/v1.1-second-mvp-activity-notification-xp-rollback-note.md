## rollback 원칙

이번 변경은 destructive rollback SQL을 즉시 실행하지 않는다. 생성된 테이블과 RPC는 additive이며 기존 V1.0/V1.1 기능의 public projection, seed, auth, hospital, walk POI canonical table을 수정하지 않는다.

운영 rollback이 필요하면 아래 순서로 진행한다.

1. 앱에서 2차 MVP read/write 연결을 비활성화한다.
2. 신규 RPC 호출 경로를 제거하거나 feature flag로 닫는다.
3. 신규 테이블의 RLS select 정책은 유지한 채 사용자 노출을 차단한다.
4. 데이터 보존 기간과 QA 데이터 삭제 범위를 별도 승인받는다.
5. destructive drop은 production owner 승인 전까지 금지한다.

## 영향 범위

- 신규 테이블: `pet_daily_activities`, `pet_streak_summaries`, `announcements`, `user_notifications`, `user_notification_reads`, `user_xp_ledger`, `user_level_summaries`, `user_titles`
- 신규/교체 RPC: `record_pet_daily_activity_v1`, `remove_pet_daily_activity_source_v1`, `get_pet_daily_status_v1`, `get_user_notification_unread_count_v1`, `get_user_notifications_v1`, `mark_user_notification_read_v1`, `award_user_activity_xp_v1`, `get_user_level_summary_v1`, `get_user_titles_v1`
- 기존 seed, walk POI, animal hospital, auth schema 직접 변경 없음

## smoke 기준

- anon RPC는 권한 없이 실패해야 한다.
- anon direct select는 row를 반환하지 않아야 한다.
- authenticated 사용자는 자기 알림/XP/streak/title만 조회해야 한다.
- source idempotency와 daily cap은 rollback보다 먼저 재검증한다.
