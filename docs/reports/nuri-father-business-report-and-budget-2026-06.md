# NURI 앱 개발 진행 보고 및 6월 운영 예산 요청서

기준일: 2026-06-30
최종 정합성 검수일: 2026-06-30
작성 목적: 가족/후원자 관점에서 현재 앱 개발 진행 상황과 2026년 6월 이후 필요한 운영 예산을 이해하기 쉽게 공유하기 위한 문서

## 1. 요약

NURI는 반려동물의 기억과 일상을 기록하고, 건강과 생활 정보를 함께 관리하는 앱이다. 보호자가 반려동물과의 추억을 사진, 글, 건강 기록, 타임라인으로 남기고, 필요한 생활 정보도 앱 안에서 확인할 수 있도록 만드는 것이 목표다.

현재 V1.0 핵심 기능은 개발과 QA 기준으로 닫힌 상태다. 회원가입, 로그인, 반려동물 등록, 커뮤니티, 건강관리, 날씨, 동물병원 찾기, 산책 장소 찾기, 보안 취약점 차단까지 주요 기능은 검증됐다.

지금은 V1.1 단계에서 산책 장소 찾기 기능을 고도화하고 있다. 특히 비싼 외부 지도 API를 사용자 앱 화면에서 계속 호출하는 구조가 아니라, 직접 관리하는 장소 데이터베이스를 만들어 장기 비용을 줄이는 방향으로 전환 중이다.

2026년 6월 말 기준 Supabase/Codex 운영비는 PO가 확정 완료했다. 따라서 이 문서의 운영비 항목은 추가 요청이 아니라 확정 상태 기록으로 유지한다. Play Store 제출 자산은 V1.0/V1.1 전체 작업과 스토어 출시 전 디자인 조정 완료 후 최종 제출 직전에 준비한다.

## 2. 지금까지 완료한 일

### 회원가입과 로그인

- 이메일 회원가입과 로그인 기능을 만들었다.
- 비밀번호 재설정 기능을 만들었다.
- Google 로그인과 Kakao 로그인을 연결했다.
- Naver 로그인은 출시 전 위험을 줄이기 위해 V1.0에서는 화면에서 닫아두었다.

### 반려동물 등록과 프로필

- 반려동물 등록 기능을 만들었다.
- 닉네임 중복확인과 닉네임 설정 흐름을 만들었다.
- 펫 생일/입양일을 직접 입력할 수 있게 개선했다.
- 예전 날짜도 `2010-05-12`처럼 빠르게 입력할 수 있다.

### 추억 기록과 타임라인

- 반려동물과의 기록을 남기고 볼 수 있는 기본 흐름을 만들었다.
- 홈, 타임라인, 전체메뉴, 편지함 등 주요 화면의 기본 동작을 확인했다.

### 커뮤니티

- 게시글과 댓글 기능의 기본 운영 방어선을 만들었다.
- 신고, 숨김 처리, 운영자 검수 기록이 남도록 했다.
- 부적절한 내용이 그대로 노출되지 않도록 최소한의 안전장치를 넣었다.

### 건강관리

- 체중 기록, 건강 기록, 월별 조회, 기본 인사이트를 만들었다.
- 입력한 체중이 반려동물 프로필과 맞게 동기화되도록 했다.
- Android 실기기에서 동작을 확인했다.

### 날씨

- 날씨 정보를 앱에서 볼 수 있게 했다.
- 외부 날씨 API를 사용자가 직접 반복 호출하지 않도록 서버 캐시 구조로 바꿨다.
- 비용과 장애 위험을 줄이는 방향으로 정리했다.

### 동물병원 찾기

- 전국 동물병원 공공 데이터를 기반으로 병원 찾기 기능을 만들었다.
- 병원 리스트와 상세 화면을 만들었다.
- 전화하기와 길찾기 기능을 연결했다.
- 비싼 Google Places/사진 API가 무분별하게 호출되지 않도록 막았다.

### 산책 장소 찾기

- V1.0에서는 Kakao Local을 서버 경유로 제한해서 비용 폭탄을 막았다.
- V1.1에서는 직접 관리하는 산책 장소 데이터베이스로 전환 중이다.
- 현재 고양시와 서울 일부 권역의 장소 데이터를 운영자 검수 방식으로 늘리고 있다.

### 관리자 검수 구조

- 장소 후보를 바로 사용자에게 보여주지 않고, 운영자가 승인한 장소만 보이도록 만들었다.
- 승인, 보류, 거절 기록이 남도록 했다.
- 운영자 화면에서 검수 상태와 기록을 확인할 수 있게 만들었다.

### 보안 취약점 차단

- 일반 사용자가 자기 권한을 관리자 권한으로 바꿀 수 있었던 중대한 취약점을 DB 레벨에서 막았다.
- 일반 프로필 수정은 유지하면서 권한 변경만 차단했다.
- release 앱에서 회귀 확인까지 완료했다.

## 3. 현재 진행 중인 일

현재 가장 중요한 작업은 산책 장소 찾기 기능의 자체 데이터 구축이다.

쉽게 말하면, 사용자가 산책 장소를 찾을 때마다 외부 지도 회사 API에 돈을 내고 물어보는 방식이 아니라, NURI가 직접 검수한 장소 데이터를 서버에 쌓아두고 앱이 그 데이터를 조회하는 구조로 바꾸고 있다.

현재 진행 상황:

- 일산/주엽/호수공원 생활권 자체 장소 데이터 확보
- 고양시 1차 장소 데이터 확대
- 서울 주요 산책 권역 1차 장소 데이터 확대
- 서울 주요 산책 권역 2차 장소 데이터 확대
- 북서울꿈의숲 보강과 수도권 1차 성남·분당·판교·탄천 장소 데이터 착수
- 수도권 2차 하남·미사, 수원·광교, 과천·서울대공원 장소 데이터 확대
- 수도권 3차 인천 송도, 부천 상동, 안양·학의천·안양천, 남양주·다산·왕숙천 장소 데이터 확대
- 전국 주요 도시 1차 부산, 대구, 대전, 울산 장소 데이터 확대
- 전국 2차 광주, 세종, 청주, 천안, 춘천, 강릉, 제주 장소 데이터 확대
- 수도권 잔여 용인·기흥, 군포, 시흥, 김포 장소 데이터 확대
- 현재 승인된 산책 장소 데이터: 1,145건
- 관리자 검수 화면 기본 구현
- 외부 API fallback은 아직 완전히 없애지 않고 안전하게 유지

다음은 V1.1 추가 업데이트 정책을 확정하고, PO 정책 확정이 필요한 리텐션 기능을 순차 구현하는 단계다.

2026년 6월 30일 기준으로 V1.1 추가 업데이트 1차 MVP 3개를 구현하고 edge QA까지 진행했다. 회원 탈퇴 시 `회원탈퇴` 직접 입력 확인을 추가했고, 로그인 화면에는 최근 로그인 방식 표시를 붙였으며, 타임라인 카테고리별 게시물 개수 표시를 추가했다. 타임라인은 실제 작성/수정/삭제 count 갱신까지 확인했고, 회원탈퇴 실제 예약과 social 최종 pill은 QA 계정 보호와 외부 OAuth/입력 자동화 제약 때문에 조건부 evidence로 남긴다. 이 작업에서 디자인 리뉴얼, Play Store 자산, DB schema, seed, migration 변경은 하지 않았다.

2026년 6월 16일 기준 작업 결과, 위 숫자는 실제 remote DB 기준과 일치한다. 현재 승인되어 사용자에게 노출 가능한 산책 장소 데이터는 305건이며, 서울 주요 산책 권역 1차/2차, 서울 보류 권역 보강, 북서울꿈의숲 보강, 성남·분당·판교·탄천 수도권 1차, 하남·미사/수원·광교/과천·서울대공원 수도권 2차까지 완료된 상태다. Android 실기기에서도 gate 적용 권역의 산책 장소 리스트, 검색, 상세, 빈 결과 화면을 확인했다. 다만 수도권 전체와 전국을 충분히 덮은 것은 아니므로 다음 단계는 수도권 3차 확장과 지역별 fallback 안정화다.

2026년 6월 17일 기준으로 수도권 3차와 전국 주요 도시 1차 확장까지 진행했다. 새로 승인한 산책 장소 데이터는 160건이며, 현재 승인되어 사용자에게 노출 가능한 산책 장소 데이터는 총 465건이다. 새로 보강한 지역은 인천 송도, 부천 상동, 안양·학의천·안양천, 남양주·다산·왕숙천, 부산 해운대·동백섬, 대구 수성못, 대전 갑천·엑스포, 울산 태화강 국가정원이다. Android 실기기에서 송도와 부산 권역의 목록, 상세, 빈 검색 화면을 직접 확인했고, 앱 오류는 없었다. 아직 전국 전체를 다 덮은 것은 아니므로 다음 단계는 전국 2차 확장과 외부 지도 API 제거 조건 검토다.

2026년 6월 19일 기준으로 전국 2차와 수도권 잔여 권역 확장까지 진행했다. 새로 승인한 산책 장소 데이터는 220건이며, 현재 승인되어 사용자에게 노출 가능한 산책 장소 데이터는 총 685건이다. 새로 보강한 지역은 광주, 세종, 청주, 천안, 춘천, 강릉, 제주와 용인·기흥, 군포, 시흥, 김포다. Android 실기기에서 광주와 시흥 권역의 목록, 상세, 빈 검색 화면을 확인했고 앱 오류는 없었다. 외부 지도 API는 아직 코드에서 삭제하지 않았지만, 어느 권역부터 안전하게 줄일 수 있는지 조건표를 만들었다.

2026년 6월 20일 기준으로는 검증된 산책 권역에서 외부 Kakao Local fallback 호출이 나가지 않도록 1단계 차단을 적용했다. 쉽게 말하면, 자체 장소 데이터가 충분하고 서버 응답이 정상인 지역에서는 앱이 자체 데이터만 사용하고 외부 지도 검색을 추가로 부르지 않는다. 다만 전국 전체, 아직 데이터가 부족한 지역, 서버 오류, 위치 정보 없음 같은 예외 상황에서는 사용자가 갑자기 빈 화면만 보지 않도록 기존 fallback을 유지한다. 외부 API 관련 코드는 아직 완전히 삭제하지 않았고, 안전하게 되돌릴 수 있는 장치를 남겨둔 상태다.

2026년 6월 21일 기준으로 전국 산책 장소 데이터 3차와 4차 확장을 실제 반영했다. 새로 승인한 산책 장소 데이터는 300건이며, 현재 승인되어 사용자에게 노출 가능한 산책 장소 데이터는 총 985건이다. 새로 보강한 지역은 전주, 창원, 포항, 김해, 여수, 순천, 목포, 구미, 진주와 부산 온천천, 대구 신천, 대전 유림공원, 울산 선암호수공원, 경주 보문호, 군산 은파호수공원 권역이다. Android 실기기에서 전주와 부산 권역의 목록, 상세 화면, 빈 검색 화면을 확인했고 앱 오류는 없었다. 외부 Kakao Local 코드는 아직 완전히 삭제하지 않고, 데이터가 충분한 권역에서 호출을 줄이는 방식으로 안전하게 진행 중이다.

## 13. 2026년 6월 22일 Kakao Local 연결 분리 및 품질 점검 추가 보고

산책 장소 기능에서 외부 Kakao Local 연결을 직접 참조하던 구조를 분리했다. 산책 기능은 산책 전용 연결 adapter를 통해서만 fallback 경로를 쓰고, 반려동물 동반 장소 검색과 동물병원 후보 보강, 행정동 조회는 기존 경로를 유지한다.

중요한 점은 Kakao Login이나 Google Login 같은 로그인 기능은 건드리지 않았다는 것이다. 이번 작업은 산책 장소 검색 비용과 안정성에 관련된 Kakao Local 장소 검색 경로만 대상으로 했다.

- 승인되어 사용자에게 노출 가능한 산책 장소 데이터: 1,145건 유지
- 새 seed 추가: 없음
- 한글 별칭 누락: 0건
- 표시용 영어 지역명 노출: 0건
- 출처/주소/분류 누락: 0건
- 승인되지 않은 데이터가 사용자 화면에 노출된 사례: 0건
- Android 실기기: 통영 권역 리스트, 상세 진입, 빈 검색 화면 확인
- 앱 오류, 멈춤, 강제 종료: 없음

외부 Kakao Local 코드는 아직 완전 삭제하지 않았다. 이유는 산책 외의 보조 기능에서도 필요한 경로가 남아 있기 때문이다. 대신 산책 기능의 직접 의존을 끊어 다음 단계에서 더 안전하게 삭제 여부를 판단할 수 있게 만들었다.

현재 산책 장소 자체 데이터 전환은 최종 검증 기준 약 99% 수준이다. 산책/location discovery 앱 runtime에서는 Kakao Local fallback을 제거했고, 자체 장소 데이터와 안전한 빈 결과 UX로 닫는다. Kakao Local 전체 provider 파일 삭제는 반려동물 동반 장소 검색, 동물병원 provider matching, 행정동 조회 경로가 남아 있어 별도 판단으로 보류한다.

## 14. 2026년 6월 22일 산책 Kakao Local fallback 종료 및 관리자 도구 개선 보고

산책 장소 기능에서는 외부 Kakao Local 장소 검색 fallback을 더 이상 사용자 runtime에서 호출하지 않도록 정리했다. 데이터가 없거나, 좌표가 없거나, 서버 검색이 실패하는 경우에도 외부 검색을 새로 부르지 않고 앱 안의 안전한 빈 결과 화면으로 처리한다.

중요한 점은 Kakao Login은 건드리지 않았다는 것이다. 반려동물 동반 장소 검색, 동물병원 후보 보강, 행정동 조회처럼 아직 Kakao Local provider가 필요한 다른 경로도 유지했다.
