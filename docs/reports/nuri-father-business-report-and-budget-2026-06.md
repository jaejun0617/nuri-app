# NURI 앱 개발 진행 보고 및 6월 운영 예산 요청서

기준일: 2026-06-15
최종 정합성 검수일: 2026-06-15
작성 목적: 가족/후원자 관점에서 현재 앱 개발 진행 상황과 2026년 6월 이후 필요한 운영 예산을 이해하기 쉽게 공유하기 위한 문서

## 1. 요약

NURI는 반려동물의 기억과 일상을 기록하고, 건강과 생활 정보를 함께 관리하는 앱이다. 보호자가 반려동물과의 추억을 사진, 글, 건강 기록, 타임라인으로 남기고, 필요한 생활 정보도 앱 안에서 확인할 수 있도록 만드는 것이 목표다.

현재 V1.0 핵심 기능은 개발과 QA 기준으로 닫힌 상태다. 회원가입, 로그인, 반려동물 등록, 커뮤니티, 건강관리, 날씨, 동물병원 찾기, 산책 장소 찾기, 보안 취약점 차단까지 주요 기능은 검증됐다.

지금은 V1.1 단계에서 산책 장소 찾기 기능을 고도화하고 있다. 특히 비싼 외부 지도 API를 사용자 앱 화면에서 계속 호출하는 구조가 아니라, 직접 관리하는 장소 데이터베이스를 만들어 장기 비용을 줄이는 방향으로 전환 중이다.

2026년 6월 25일에 Codex 앱 사용/결제 종료 또는 갱신 시점이 있어, 다음 한 달 개발을 이어가기 위한 Codex 앱 예산과 Supabase 서버 운영 예산이 필요하다.

## 2. 지금까지 완료한 일

### 회원가입과 로그인

- 이메일 회원가입과 로그인 기능을 만들었다.
- 비밀번호 재설정 기능을 만들었다.
- Google 로그인과 Kakao 로그인을 연결했다.
- Naver 로그인은 출시 전 위험을 줄이기 위해 V1.0에서는 화면에서 닫아두었다.

### 반려동물 등록과 프로필

- 반려동물 등록 기능을 만들었다.
- 닉네임 중복확인과 닉네임 설정 흐름을 만들었다.
- 펫 생일/입양일을 직접 입력할 수 있게 개선했다.
- 예전 날짜도 `2010-05-12`처럼 빠르게 입력할 수 있다.

### 추억 기록과 타임라인

- 반려동물과의 기록을 남기고 볼 수 있는 기본 흐름을 만들었다.
- 홈, 타임라인, 전체메뉴, 편지함 등 주요 화면의 기본 동작을 확인했다.

### 커뮤니티

- 게시글과 댓글 기능의 기본 운영 방어선을 만들었다.
- 신고, 숨김 처리, 운영자 검수 기록이 남도록 했다.
- 부적절한 내용이 그대로 노출되지 않도록 최소한의 안전장치를 넣었다.

### 건강관리

- 체중 기록, 건강 기록, 월별 조회, 기본 인사이트를 만들었다.
- 입력한 체중이 반려동물 프로필과 맞게 동기화되도록 했다.
- Android 실기기에서 동작을 확인했다.

### 날씨

- 날씨 정보를 앱에서 볼 수 있게 했다.
- 외부 날씨 API를 사용자가 직접 반복 호출하지 않도록 서버 캐시 구조로 바꿨다.
- 비용과 장애 위험을 줄이는 방향으로 정리했다.

### 동물병원 찾기

- 전국 동물병원 공공 데이터를 기반으로 병원 찾기 기능을 만들었다.
- 병원 리스트와 상세 화면을 만들었다.
- 전화하기와 길찾기 기능을 연결했다.
- 비싼 Google Places/사진 API가 무분별하게 호출되지 않도록 막았다.

### 산책 장소 찾기

- V1.0에서는 Kakao Local을 서버 경유로 제한해서 비용 폭탄을 막았다.
- V1.1에서는 직접 관리하는 산책 장소 데이터베이스로 전환 중이다.
- 현재 고양시와 서울 일부 권역의 장소 데이터를 운영자 검수 방식으로 늘리고 있다.

### 관리자 검수 구조

- 장소 후보를 바로 사용자에게 보여주지 않고, 운영자가 승인한 장소만 보이도록 만들었다.
- 승인, 보류, 거절 기록이 남도록 했다.
- 운영자 화면에서 검수 상태와 기록을 확인할 수 있게 만들었다.

### 보안 취약점 차단

- 일반 사용자가 자기 권한을 관리자 권한으로 바꿀 수 있었던 중대한 취약점을 DB 레벨에서 막았다.
- 일반 프로필 수정은 유지하면서 권한 변경만 차단했다.
- release 앱에서 회귀 확인까지 완료했다.

## 3. 현재 진행 중인 일

현재 가장 중요한 작업은 산책 장소 찾기 기능의 자체 데이터 구축이다.

쉽게 말하면, 사용자가 산책 장소를 찾을 때마다 외부 지도 회사 API에 돈을 내고 물어보는 방식이 아니라, NURI가 직접 검수한 장소 데이터를 서버에 쌓아두고 앱이 그 데이터를 조회하는 구조로 바꾸고 있다.

현재 진행 상황:

- 일산/주엽/호수공원 생활권 자체 장소 데이터 확보
- 고양시 1차 장소 데이터 확대
- 서울 주요 산책 권역 1차 장소 데이터 확대
- 서울 주요 산책 권역 2차 장소 데이터 확대
- 현재 승인된 산책 장소 데이터: 130건
- 관리자 검수 화면 기본 구현
- 외부 API fallback은 아직 완전히 없애지 않고 안전하게 유지

다음은 서울에서 아직 촘촘하지 않은 권역과 수도권 주요 산책 권역을 보강하고, 이후 전국으로 넓히는 단계다.

2026년 6월 15일 기준 작업 결과, 위 숫자는 실제 remote DB 기준과 일치한다. 현재 승인되어 사용자에게 노출 가능한 산책 장소 데이터는 130건이며, 서울 주요 산책 권역 1차와 2차 확장은 완료된 상태다. 다만 서울 전체와 전국을 충분히 덮은 것은 아니므로 다음 단계는 수도권과 서울 보류 권역 보강이다.

현재 진행률 요약:

| 구분 | 진행률 | 쉬운 설명 |
| --- | ---: | --- |
| V1.0 핵심 기능 | 100% | 출시 기준 핵심 기능과 보안 문제는 닫힌 상태 |
| V1.0 QA/출시 준비 | 약 96% | 실기기 검증과 release 확인은 끝났고, Play Store 제출용 이미지/문구 준비가 남음 |
| V1.1 산책 장소 자체 데이터 전환 | 약 72% | 고양시와 서울 1차/2차 데이터, 관리자 검수 구조는 됐고 수도권/전국 확장이 남음 |
| V1.1 전체 | 약 32% | 산책 장소 외에도 결제, AI, 편지함, 디자인 정리 등 장기 작업이 남음 |
| 전체 제품 로드맵 | 약 74% | V1.0은 닫혔고 V1.1 핵심 기반과 서울 2차 보강을 진행함 |
| 최종 제출 준비 | 약 20% | Play Store 스크린샷, 설명문, Console 입력은 아직 마지막 단계로 남음 |

## 8. 왜 예산이 필요한가

NURI는 이미 핵심 기능 개발이 상당히 진행된 상태다. 하지만 앱을 안정적으로 출시하고 운영하려면 마지막 고도화와 QA, 서버 운영비가 필요하다.

특히 지금은 산책 장소 데이터를 직접 관리하는 구조로 바꾸고 있다. 이 작업은 당장 개발 시간이 필요하지만, 장기적으로는 외부 지도 API 비용을 줄이는 방향이다.

비용 절감 조치:

- Google Places runtime 차단
- Google Place Photos runtime 차단
- Kakao Local 사용자 runtime 단계적 축소
- 자체 POI DB 구축
- 서버 캐시 적용
- 외부 API는 운영자 batch 보조 도구로 제한

## 9. 아버지에게 전달할 결론

현재 앱은 핵심 기능 개발과 주요 QA가 거의 끝났고, 출시 전 마지막 고도화와 안정화 단계에 있다.

6월 25일 이후에도 개발을 이어가려면 Codex 앱 한 달치와 Supabase 운영비가 필요하다. 이 비용은 무작정 쓰는 돈이 아니라 출시와 운영 안정화를 위한 최소 개발/서버 운영 비용이다.

특히 산책 장소 기능은 비싼 지도 API를 계속 쓰는 구조가 아니라, 직접 검수한 장소 데이터를 쌓아 장기 비용을 줄이는 방향으로 바꾸고 있다. 지금 필요한 예산은 NURI를 출시 가능한 서비스로 안정화하고, 이후 전국 확장까지 이어가기 위한 현실적인 운영 자금이다.
