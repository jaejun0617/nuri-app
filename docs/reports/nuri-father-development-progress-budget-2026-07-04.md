## 1. 한 줄 요약

NURI 앱은 V1.0 핵심 기능과 V1.1 주요 업데이트까지 release-ready 수준으로 올라왔고, 현재는 V1.1.1의 활동·칭호 대시보드 안정화와 다음 운영 기능 우선순위 확정 단계다.

현재 기준으로 큰 개발 blocker는 없으며, 남은 비용은 주로 AI 개발 도구 비용, Supabase 운영비, 스토어 제출 전 디자인 polish, 향후 push/운영자 발송 관리 같은 후속 기능 개발비다.

## 4. 남은 개발 작업

### 1순위: 운영자 알림 발송 관리 체계

앱 내부 admin 화면이 아니라 별도 홈페이지/관리 페이지 트랙으로 설계한다.

필요 범위:

- 운영자 로그인/권한
- 알림 템플릿
- 발송 대상 범위
- 발송 전 검수
- 취소/숨김 정책
- audit log
- QA fixture
- push 알림과 연결하기 전 안전한 앱 내부 알림 row 생성 경로

### 2순위: push 알림

운영자 발송 정책이 먼저 있어야 한다.

필요 범위:

- FCM 또는 플랫폼 push 설계
- push token 저장
- 알림 권한 UX
- opt-out 정책
- 개인정보 고지
- delivery log
- 실패/재시도 정책

### 3순위: 휴대폰 홈 위젯

Android native AppWidget 재설계가 필요하다.

필요 범위:

- 개인정보 노출 범위
- 어떤 데이터를 widget에 보여줄지
- 업데이트 주기
- 배터리 영향
- Android release manifest 재활성 기준

### 4순위: 무지개다리 서비스

감정적으로 민감한 기능이므로 기능보다 문구와 정책을 먼저 설계한다.

필요 범위:

- 노출 조건
- 한 번만 제안하는 UX
- 상품/문의/결제 정책
- 사용자가 불편하지 않은 문구 검토

### 별도 트랙

- 스토어 출시 전 디자인 polish
- Play Store 스크린샷/설명문/스토어 자산
- 장기 유료화/AI 기능
- 고급 랭킹/리더보드

## 7. Supabase 운영비

보고서 예산에는 Supabase를 월 `약 10만원`으로 잡는다.

Supabase 공식 billing 문서 기준 Pro/Team 계열은 주요 포함량이 아래와 같다.

- Monthly Active Users: `100,000 MAU` 포함, 초과 시 `$0.00325 / MAU`
- Database Size: `8GB` 포함, 초과 시 `$0.125 / GB`
- Egress: `250GB` 포함, 초과 시 `$0.09 / GB`
- Storage Size: `100GB` 포함, 초과 시 `$0.021 / GB`
- Edge Function Invocations: `2,000,000회` 포함, 초과 시 `$2 / 1,000,000회`
- Realtime Messages: `5,000,000건` 포함, 초과 시 `$2.5 / 1,000,000건`

중요한 점:

- Supabase 비용은 “총 회원가입 계정 수”보다 “월간 활성 사용자 수(MAU)”가 더 중요하다.
- 가입만 하고 그 달에 거의 접속하지 않는 사용자는 MAU 비용에 크게 영향을 주지 않을 수 있다.
- NURI처럼 이미지, 알림, 타임라인, 위치 기능이 있는 앱은 MAU 외에도 저장공간, egress, Edge Function 호출량을 같이 봐야 한다.

단순 Auth MAU만 보면 Supabase Pro 포함량은 `100,000 MAU`까지다. 월 10만원 예산은 base 비용과 약간의 초과 사용량 buffer를 포함한 관리 예산으로 보면 된다.

현실적인 운영 판단:

- 출시 초기: 1만~3만 MAU까지는 월 10만원 예산으로 충분히 방어 가능
- 성장 구간: 5만~10만 MAU는 가능하지만 egress, storage, Edge Function을 주간 모니터링해야 함
- 10만 MAU 초과: 추가 비용이 선형으로 붙기 시작하므로 운영 예산 증액 필요
- 20만 MAU 이상: Supabase 비용만 월 수십만원 이상으로 올라갈 수 있으므로 요금제, 캐싱, 이미지 저장/전송 정책, 알림 구조 최적화 필요
