## Admin Workflow Smoke Data

admin import commit/review workflow 검증용 row는 `nuri-v1.1-admin-smoke-` prefix를 사용한다.

운영 기준:

- 검증 중 approved/public 상태로 잠깐 승격할 수 있다.
- 검증 종료 시 `held/hidden`으로 내려 public projection에서 제외한다.
- delete가 아니라 held 처리로 audit trail을 유지한다.
- public search/nearby/detail RPC에서 admin smoke row가 노출되면 blocker다.

## Seed Coverage 확대 기준

seed coverage 확대는 아래 기준을 만족할 때만 진행한다.

- source provenance가 명확함
- 좌표가 WGS84 기준으로 검증 가능함
- category가 `walk_pois.category` enum에 매핑 가능함
- duplicate/conflict 검토 기준이 있음
- admin review queue로 pending 후보를 분리할 수 있음
- rejected/held/pending이 public projection에 노출되지 않음

초기 대상:

- 공공데이터 park/green space source
- OSM park/trail/path 후보
- 운영자 승인 seed
- Kakao Local은 사용자 runtime이 아니라 admin seed 보조 후보로만 제한

## Fallback 축소 전 기준

Kakao fallback 축소는 seed 양만으로 판단하지 않는다.

필수 gate:

- 반경 3km 내 approved/public/active POI 10건 이상
- 반경 5km 내 approved/public/active POI 20건 이상
- 주요 검색어 hit-rate 70% 이상
- nearby empty result 비율 20% 이하
- fallback 호출 비율 30% 이하
- public RPC error rate 1% 이하
- public projection 누수 0건
- rollback/held 처리 절차 준비
- Android 실기기 산책 리스트/검색/상세 smoke 통과

축소하지 않는 조건:

- coverage가 낮아 사용자가 기존보다 결과를 적게 받음
- fallback 호출률이 높음
- 운영자가 source provenance를 설명할 수 없음
- seed conflict가 unresolved 상태임

## Rollback / Held 정책

운영 데이터 삭제는 기본 전략이 아니다. 문제가 생긴 seed는 우선 public projection에서 제외한다.

우선 순서:

1. `walk_pois.review_status = 'held'`
2. `walk_pois.visibility_status = 'hidden'`
3. `walk_poi_source_records.candidate_status = 'held'`
4. audit log에 조치 이유 기록

delete는 잘못 적재된 raw payload나 개인정보성 데이터가 들어간 경우에만 별도 승인 후 수행한다.
