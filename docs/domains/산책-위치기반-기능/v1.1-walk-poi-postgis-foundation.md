# V1.1 산책 POI PostGIS Foundation

업데이트: 2026-06-06

## 배경

V1.0에서는 지도/API 비용 폭탄 방어 gate를 닫았다. Google Places/Photos 경로는 차단되었고, Kakao Local은 클라이언트 직접 호출 없이 서버 경유·캐시·fan-out 제한 상태로 통제한다. 단, Kakao Local은 provider-zero가 아니므로 V1.1에서는 산책/location discovery를 자체 POI DB + Supabase PostGIS 기반 반경 검색으로 전환한다. Kakao Local은 사용자 runtime에서 제거하고, 필요 시 admin seed 보조 도구로만 제한한다.

이번 foundation 작업은 앱 산책 화면을 즉시 전환하지 않는다. 기존 `location-discovery-seed`와 Kakao Local controlled-server-call 경로는 그대로 유지하고, 자체 POI read path로 전환할 수 있는 DB/RLS/RPC 기반을 병행 추가한다.

## 현재 V1.0 Runtime

- 앱 `useLocationDiscovery`는 `searchLocationDiscovery`를 호출한다.
- `searchLocationDiscovery`는 산책 도메인에서 Kakao keyword 후보를 수집하고, 산책용 positive/negative keyword와 fan-out 제한으로 후보를 정제한다.
- 앱 클라이언트는 Kakao REST API key를 직접 보유하지 않는다.
- `src/services/locationDiscovery/kakaoLocal.ts`는 Supabase Edge Function `location-discovery-seed`만 호출한다.
- `location-discovery-seed` Edge Function은 Kakao keyword/address/coord2region 호출을 서버에서 수행하며, 10분 메모리 캐시와 요청 normalization을 가진다.

## 목표 구조

V1.1 자체 POI 구조는 아래 layer를 분리한다.

- canonical layer: NURI가 검수/승인한 자체 산책 POI 기준 데이터
- source/import layer: 공공데이터, OSM, 운영자 seed, Kakao Local admin 보조 후보의 원본 추적
- review/audit layer: 운영자 검수, merge, visibility 변경, import 이력
- public projection layer: 앱 runtime이 읽는 approved/visible 필드만 반환하는 RPC

## 2026-06-04 앱 Read Path 병행 전환

이번 단계에서는 앱 산책/location discovery read path를 자체 POI public RPC 우선 구조로 병행 전환했다.

적용 방식:

- `EXPO_PUBLIC_ENABLE_WALK_POI_RPC=true`이면 산책 nearby/search/detail에서 자체 POI public RPC를 먼저 호출한다.
- 자체 POI 결과가 1건 이상이면 기존 `LocationDiscoveryItem` 카드 모델로 변환해 표시한다.
- 자체 POI 결과가 0건이거나 RPC 호출이 실패하면 기존 `location-discovery-seed` Edge Function + Kakao Local 서버 경유 경로로 fallback한다.
- Kakao Local fallback은 이번 턴에서 삭제하지 않았다.
- canonical POI 결과는 Google/Kakao provider thumbnail enrichment 요청 대상에서 제외한다.

앱 연결 파일:

- `src/services/locationDiscovery/walkPoiRpc.ts`
- `src/services/locationDiscovery/service.ts`
- `src/screens/LocationDiscovery/LocationDiscoveryDetailScreen.tsx`
- `src/services/placeEnrichment/service.ts`

POI result mapping:

- `provider = 'walk_poi'`
- `providerLabel = 'NURI 자체 POI'`
- `source.type = 'canonical-poi'`
- `verification.status = 'admin-verified'`
- `publicTrust.publicLabel = 'trust_reviewed'`
- `qualityScore`는 public RPC의 `quality_score`를 nullable-safe로 매핑한다.
- public RPC가 반환하지 않는 source/import/review/audit 내부 필드는 앱에서 기대하지 않는다.

Fallback 기준:

- `poi_disabled`: feature flag disabled
- `coordinate_missing`: nearby anchor coordinate 없음
- `poi_rpc_error`: RPC timeout/error
- `poi_empty`: nearby/search 결과 0건
- `detail_not_found`: detail RPC 0건

Fallback 시 기존 산책 UX는 그대로 Kakao Local 서버 경유 결과를 표시한다. 사용자는 기존 화면 구조와 동일하게 리스트/상세/지도 보기 흐름을 사용한다.

## 2026-06-05 Admin Import / Review Workflow

이번 단계에서는 dry-run 이후 운영자가 후보를 실제 source/import/review layer에 적재하고, 검수 action으로 public projection 승격 여부를 결정하는 서버 계약을 추가했다.

적용 migration:

- `20260605090000_walk_poi_admin_import_review_workflow.sql`
- `20260605093000_walk_poi_admin_review_alias_conflict_fix.sql`

추가 RPC:

- `walk_poi_admin_import_commit_v1`
- `walk_poi_admin_review_v1`

권한 정책:

- admin/super_admin만 import commit/review 가능
- anon은 admin RPC execute 권한 없음
- 비관리자 authenticated는 `WALK_POI_ADMIN_REQUIRED`로 거부
- public table direct read는 계속 차단

Review 정책:

- commit은 hidden/pending canonical candidate, source record, pending review row, audit log를 만든다.
- approve는 `approved/public/active`로 승격하고 public RPC에서 반환한다.
- reject/held는 `hidden` 상태를 유지하며 public RPC에서 반환하지 않는다.
- 모든 action은 review/audit log에 남긴다.

Public projection safety:

- approved/public/active row만 반환한다.
- pending/rejected/held row는 앱 public RPC에서 반환하지 않는다.
- raw/source/review/audit 내부값은 public RPC에 노출하지 않는다.

상세 계약:

- `docs/domains/산책-위치기반-기능/v1.1-walk-poi-admin-import-review.md`

공개 조건:

### `walk_poi_import_batches`

운영자 import batch ledger다. dry-run과 commit batch를 분리하고, source/provider, 상태, summary, 시작/종료 시각을 추적한다.

### `walk_poi_source_records`

source/import 후보 원본이다. provider raw payload, external id, source 좌표, 후보 상태, confidence score를 보관한다. 이 테이블은 public surface에 직접 노출하지 않는다.

### `walk_poi_reviews`

운영자 검수 결정 기록이다. approved/rejected/held 상태와 reviewer note, diff를 남긴다.

### `walk_poi_audit_logs`

POI import, review, merge, visibility, canonical 변경 이력을 남기는 admin-only audit log다.

### `walk_poi_search_aliases`

검색 별칭과 한국어 place name 변형을 저장한다.

목적:

- 비관리자는 `WALK_POI_ADMIN_REQUIRED`로 거부

Payload contract:

```json
{
  "externalSourceId": "public-data:seoul:park:123",
  "name": "서울광장",
  "category": "park",
  "categoryLabel": "광장",
  "address": "서울특별시 중구 세종대로 110",
  "roadAddress": "서울특별시 중구 세종대로 110",
  "latitude": 37.566289,
  "longitude": 126.97793,
  "aliases": ["서울 시청 광장", "시청앞광장"],
  "attribution": "공공데이터 또는 운영자 승인 seed",
  "confidenceScore": 90,
  "qualityScore": 80,
  "rawPayload": {
    "source": "admin-import"
  }
}
```

Conflict key 후보:

- `source_provider + externalSourceId`
- name/address/coordinate proximity
- normalized alias overlap

Dry-run result:

- `ok`
- `source_provider`
- `candidate_count`
- `message`

Commit/review 후속:

- dry-run이 통과한 후보만 import batch commit으로 넘긴다.
- commit은 source record 생성과 candidate/review queue 적재를 분리한다.
- public 노출은 admin review에서 approved/public/active로 승격된 뒤에만 가능하다.

## RLS 정책

기본 원칙:

- anonymous/public client는 source/import/review/audit/canonical table을 직접 읽지 않는다.
- public read는 `SECURITY DEFINER` RPC로 좁게 노출한다.
- RPC는 approved/visible/active 조건을 강제한다.
- `authenticated`의 직접 table 접근은 admin/super_admin만 RLS policy로 허용한다.
- 일반 사용자의 직접 write는 금지한다.

확인 결과:

- `anon` 역할의 `walk_poi_public_search_v1` 호출은 성공하고 빈 seed 상태에서 0건을 반환했다.

## 앱 화면 영향

이번 foundation 작업에서는 앱 화면 영향이 없다.

다음 전환 작업에서 필요한 앱 변경:

- `LocationDiscoverySource`에 자체 POI RPC source를 명시
- 산책 nearby/search read path를 `walk_poi_public_nearby_v1`/`walk_poi_public_search_v1`로 전환
- 자체 POI 결과 없음 상태는 provider retry가 아니라 empty/fallback UX로 처리
- Kakao Local fallback은 admin seed coverage 전환 기준이 충족될 때 사용자 runtime에서 제거
- 상세 화면은 `walk_poi_public_detail_v1` projection만 사용

## Rollback 기준

이번 migration은 additive이므로 rollback이 필요한 경우 앱 runtime은 기존 `location-discovery-seed` 경로를 계속 사용한다.

rollback 또는 보류 기준:

- public RPC가 unapproved/hidden/internal row를 반환하는 경우
- anon이 source/import/review/audit table을 직접 읽는 경우
- admin dry-run이 비관리자에게 열리는 경우
- PostGIS index가 radius query에서 사용되지 않아 latency가 release 기준을 넘는 경우
- seed coverage가 낮아 산책 리스트 기본 UX가 크게 퇴화하는 경우
