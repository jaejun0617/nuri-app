# V1.1 산책 POI PostGIS Foundation

업데이트: 2026-06-04

## 배경

V1.0에서는 지도/API 비용 폭탄 방어 gate를 닫았다. Google Places/Photos 경로는 차단되었고, Kakao Local은 클라이언트 직접 호출 없이 서버 경유·캐시·fan-out 제한 상태로 통제한다. 단, Kakao Local은 provider-zero가 아니므로 V1.1에서는 산책/location discovery를 자체 POI DB + Supabase PostGIS 기반 반경 검색으로 전환한다. Kakao Local은 사용자 runtime에서 제거하고, 필요 시 admin seed 보조 도구로만 제한한다.

이번 foundation 작업은 앱 산책 화면을 즉시 전환하지 않는다. 기존 `location-discovery-seed`와 Kakao Local controlled-server-call 경로는 그대로 유지하고, 자체 POI read path로 전환할 수 있는 DB/RLS/RPC 기반을 병행 추가한다.

## 현재 V1.0 Runtime

- 앱 `useLocationDiscovery`는 `searchLocationDiscovery`를 호출한다.
- `searchLocationDiscovery`는 산책 도메인에서 Kakao keyword 후보를 수집하고, 산책용 positive/negative keyword와 fan-out 제한으로 후보를 정제한다.
- 앱 클라이언트는 Kakao REST API key를 직접 보유하지 않는다.
- `src/services/locationDiscovery/kakaoLocal.ts`는 Supabase Edge Function `location-discovery-seed`만 호출한다.
- `location-discovery-seed` Edge Function은 Kakao keyword/address/coord2region 호출을 서버에서 수행하며, 10분 메모리 캐시와 요청 normalization을 가진다.

## 목표 구조

V1.1 자체 POI 구조는 아래 layer를 분리한다.

- canonical layer: NURI가 검수/승인한 자체 산책 POI 기준 데이터
- source/import layer: 공공데이터, OSM, 운영자 seed, Kakao Local admin 보조 후보의 원본 추적
- review/audit layer: 운영자 검수, merge, visibility 변경, import 이력
- public projection layer: 앱 runtime이 읽는 approved/visible 필드만 반환하는 RPC

## Remote 적용 상태

마이그레이션 `20260604110000_walk_poi_postgis_foundation.sql`을 linked Supabase remote에 적용했다.

적용 범위:

- `postgis` extension enable
- `pg_trgm` extension 확인
- `walk_pois`
- `walk_poi_import_batches`
- `walk_poi_source_records`
- `walk_poi_reviews`
- `walk_poi_audit_logs`
- `walk_poi_search_aliases`
- `is_walk_poi_admin()`
- `sync_walk_poi_location()`
- `walk_poi_public_search_v1`
- `walk_poi_public_nearby_v1`
- `walk_poi_public_detail_v1`

V1.0 runtime 영향:

- 기존 산책 화면 query는 변경하지 않았다.
- `location-discovery-seed`는 삭제하거나 수정하지 않았다.
- Kakao Local 사용자 runtime 경로는 이번 턴에서 제거하지 않았다.
- 신규 table/function/RLS/index만 추가한 additive migration이다.

## Schema 초안

### `walk_pois`

자체 POI canonical row다.

주요 필드:

- `canonical_name`, `normalized_name`
- `category`, `category_label`
- `primary_address`, `road_address`, `lot_address`
- `latitude`, `longitude`
- `location geography(Point, 4326)`
- `lifecycle_status`
- `visibility_status`
- `review_status`
- `quality_score`
- `source_attribution`
- `primary_source_provider`
- `source_updated_at`
- `last_reviewed_at`
- `metadata`
- `search_text`

공개 조건:

- `lifecycle_status = 'active'`
- `visibility_status = 'public'`
- `review_status = 'approved'`

### `walk_poi_import_batches`

운영자 import batch ledger다. dry-run과 commit batch를 분리하고, source/provider, 상태, summary, 시작/종료 시각을 추적한다.

### `walk_poi_source_records`

source/import 후보 원본이다. provider raw payload, external id, source 좌표, 후보 상태, confidence score를 보관한다. 이 테이블은 public surface에 직접 노출하지 않는다.

### `walk_poi_reviews`

운영자 검수 결정 기록이다. approved/rejected/held 상태와 reviewer note, diff를 남긴다.

### `walk_poi_audit_logs`

POI import, review, merge, visibility, canonical 변경 이력을 남기는 admin-only audit log다.

### `walk_poi_search_aliases`

검색 별칭과 한국어 place name 변형을 저장한다.

## Index 설계

- `walk_pois.location` GiST index
- public 상태 조건 index
- `canonical_name` trigram index
- `search_text` trigram index
- `search_text` full-text expression index
- source provider + external id unique partial index
- import batch/candidate status index
- review/audit 시간순 index
- alias trigram index

## RPC/API 설계

### `walk_poi_public_search_v1`

목적:

- query, anchor coordinate, radius, bbox를 함께 받는 public-safe 검색
- approved/visible/active POI만 반환
- 내부 source payload, review state, audit 값은 반환하지 않음

반환 필드:

- `id`
- `name`
- `category`
- `category_label`
- `description`
- `address`
- `road_address`
- `latitude`
- `longitude`
- `distance_meters`
- `source_attribution`
- `public_trust_status`
- `reviewed_at`
- `updated_at`
- `quality_score`

### `walk_poi_public_nearby_v1`

목적:

- anchor coordinate 기반 주변 산책 POI 조회
- 내부적으로 search RPC와 같은 projection을 사용

### `walk_poi_public_detail_v1`

목적:

- approved/visible/active 단일 POI 상세 projection 반환

### `walk_poi_admin_import_dry_run_v1`

목적:

- admin/super_admin 전용 import dry-run payload validation
- 이번 foundation에서는 실제 commit/import write를 수행하지 않음
- 비관리자는 `WALK_POI_ADMIN_REQUIRED`로 거부

## RLS 정책

기본 원칙:

- anonymous/public client는 source/import/review/audit/canonical table을 직접 읽지 않는다.
- public read는 `SECURITY DEFINER` RPC로 좁게 노출한다.
- RPC는 approved/visible/active 조건을 강제한다.
- `authenticated`의 직접 table 접근은 admin/super_admin만 RLS policy로 허용한다.
- 일반 사용자의 직접 write는 금지한다.

확인 결과:

- `anon` 역할의 `walk_poi_public_search_v1` 호출은 성공하고 빈 seed 상태에서 0건을 반환했다.
- `anon` 역할의 `walk_pois` 직접 SELECT는 permission denied로 차단됐다.
- `authenticated` 비관리자 컨텍스트의 admin dry-run RPC는 `WALK_POI_ADMIN_REQUIRED`로 차단됐다.
- rollback 트랜잭션 안에서 임시 approved POI를 넣어 `walk_poi_public_nearby_v1`, `walk_poi_public_search_v1`, `walk_poi_public_detail_v1`이 각각 1건을 반환하는 것을 확인했다. 테스트 row는 rollback되어 운영 데이터에 남기지 않았다.

## Data Source 후보

- 공공데이터: 공원, 산책로, 반려동물 동반 가능 시설, 지자체 개방 데이터
- OSM: park, path, trail, greenspace, dog 관련 geometry/tag seed
- 운영자 승인 seed: NURI 운영자가 검수한 산책/공원/동반 가능 지점
- Kakao Local: 사용자 runtime이 아니라 admin seed 보조 후보로만 제한

## 앱 화면 영향

이번 foundation 작업에서는 앱 화면 영향이 없다.

다음 전환 작업에서 필요한 앱 변경:

- `LocationDiscoverySource`에 자체 POI RPC source를 명시
- 산책 nearby/search read path를 `walk_poi_public_nearby_v1`/`walk_poi_public_search_v1`로 전환
- 자체 POI 결과 없음 상태는 provider retry가 아니라 empty/fallback UX로 처리
- Kakao Local fallback은 admin seed coverage 전환 기준이 충족될 때 사용자 runtime에서 제거
- 상세 화면은 `walk_poi_public_detail_v1` projection만 사용

## Rollback 기준

이번 migration은 additive이므로 rollback이 필요한 경우 앱 runtime은 기존 `location-discovery-seed` 경로를 계속 사용한다.

rollback 또는 보류 기준:

- public RPC가 unapproved/hidden/internal row를 반환하는 경우
- anon이 source/import/review/audit table을 직접 읽는 경우
- admin dry-run이 비관리자에게 열리는 경우
- PostGIS index가 radius query에서 사용되지 않아 latency가 release 기준을 넘는 경우
- seed coverage가 낮아 산책 리스트 기본 UX가 크게 퇴화하는 경우

## 다음 구현 프롬프트 초안

V1.1 산책/location discovery 자체 POI foundation migration은 remote에 적용됐다. 다음 턴에서는 앱 산책 read path를 기존 Kakao Local provider가 아니라 `walk_poi_public_nearby_v1`, `walk_poi_public_search_v1`, `walk_poi_public_detail_v1` 기반으로 병행 전환한다. 기존 UI는 유지하고, empty/fallback UX는 provider retry가 아니라 자체 POI coverage 부족 상태로 처리한다. Kakao Local은 사용자 runtime에서 즉시 hard delete하지 말고, 자체 POI 결과가 정상 동작하는지 Android 실기기 smoke로 확인한 뒤 admin seed 보조 도구로만 제한하는 gate를 문서화한다.
