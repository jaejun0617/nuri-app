# 누리 출시 전 잔여와 후속 제품 기획

2026-11-22 KST · Master 검토 정본 · **D만 기존 승인으로 진행. 이 문서의 제안은 실행·출시 승인이 아니다.**

**결론:** 출시 전에는 사용자가 로그인하고, 자기 펫을 선택하고, 기록과 문의를 읽고 쓰는 기존 흐름이 깨지는 문제를 먼저 닫는다. 품종을 찾거나 내 댓글로 돌아가는 개선은 이 목적에 맞지만, 다른 사람의 활동을 모아 보여주는 일은 별도의 공개 결정이다. 전면 리디자인·일촌·AI를 출시의 전제에서 뺀다. 요구 자체는 아래 대응표에 보존한다.

### UI-04. 날씨 상세: 같은 계절 풍경의 낮과 밤

첫 화면에서는 위치·현재 기온·날씨를 풍경 위에서 읽고, 아래로 내려가면 같은 하늘색 위에 놓인 패널에서 외출할 시간의 강수와 일주일 예보를 확인한다. 풍경만 보이는 별도 표지나 장식용 카드를 추가하지 않는다. 계절은 **풍경**, 낮·밤은 **빛**, 현재 날씨는 **하늘과 지면의 상태**를 결정한다. 자료가 없어도 쓸 수 있는 화면이어야 한다.

| 참고 영상에서 본 것 | 누리에 적용할 배경·패널 | 정보가 읽히는 방식 |
| --- | --- | --- |

| 흐린 밤 · 두 번째 영상(약 57초 · 1080×2340)의 회청색 구름, 어두운 지평선, 남청·인디고 본문. | 시안 시작색: 회청 `#505E79` → 지평선 `#2C3B52` → 본문 `#394571`. 글라스는 남청 `rgba(18,31,54,0.50)`. 구름과 채광만 바꾸고 **빗결·젖은 반사는 쓰지 않는다.** | 본문은 미색, 보조 문구는 밝은 회청색. 흐림 상태명과 아이콘을 유지한다. |

위 색은 확정값이 아니라 시안 출발값이다. 넓은 패널과 부드러운 모서리를 유지하고 면의 밝기 차로 구분한다. 상단 안전영역부터 마지막 패널 아래까지 배경을 잇는다. 실제 이미지·패널을 합성하고 크롭한 결과를 기준으로 본문·보조 문구·날짜·단위·입력 안내는 4.5:1 이상, 의미 있는 아이콘·그래프·선택 표시는 인접 배경과 3:1 이상을 확인한다. TalkBack에서 요약 → 시간대 → 주간 순서와 그래프의 수치·단위 대체 설명을 확인하고 장식 풍경은 중복 낭독하지 않는다.

관측 자료가 갱신될 때는 날씨 코드·주야·관측 시점을 한 묶음으로 사용한다. 이전 응답의 주야와 새 응답의 코드를 섞지 않는다. 근거가 빠지면 중립 장면을 사용하고 오래된 값은 시점을 표시한다. 자산 매핑에는 그림에 이미 포함된 달·별·광원·눈·젖은 반사를 기록한다. 실제 상태와 충돌하면 레이어로 억지로 덮지 않고 중립 자산으로 대체한다.

**출시 경계:** 현재 날씨 정보 오류·읽기 불가·조작 불가만 기존 결함으로 선별한다. 새 계절 재질과 PO 시각 확정은 출시 게이트가 아니다. 품종 검색과 내 글·댓글 모음도 후속 편의다. 기존 등록·직접 입력·원문 접근에 결함이 있으면 그 결함만 출시 대상으로 본다.

4. 현재 요약 다음에는 시간대별 강수·7일 예보를 읽을 수 있게 하고, 대기질·생활 지표·외출 전 체크 등 기존 정보는 아래에서 이어 본다. 정보량이나 기능을 줄여 재질을 맞추지 않는다. **향후 시안·수락 순서:** 먼저 같은 계절·같은 위치에서 맑은 낮, 흐린 밤, 비 오는 밤 세 장면을 비교한다. 흐린 밤과 비 오는 밤은 강수 수치가 아니라 풍경과 실제 상태명만으로도 구별돼야 한다. 다음은 계절 4종과 눈(가을 공용 대체 포함), 맑은 밤·흐린 낮, 위치/날씨 미확인·갱신 실패를 확인한다. 32개 기본 조합은 상태와 자산 연결 검사로 확인하고, 네이티브 화면에서는 밝은 낮의 저대비·밤의 보조 글자·눈의 밝은 배경 등 위험 조합을 우선한다. 320dp 큰 글자(시스템 1.5·2.0)에서 강수 3칸, 예보의 날짜·아이콘·숫자, 본문 끝 스크롤과 Back, 상태바 가독성을 확인한다. 이 절은 **설계 반영**이며 시안 생성·제품 적용·실기기 수락은 별도다.

## 3. ‘누리를 소개합니다’ 사진: 오류 지점을 먼저 나눈다

**판정: 증상 접수, 해당 게시물 원인·복구 여부 미확인.** 제목은 식별자가 아니다. 비공개로 게시물 식별자·첨부 순번, 목록/홈/상세/확대 중 진입점과 시각, 설치 후보·계정 역할·네트워크·재진입 변화, 가능하면 당시 오류 화면을 한 번에 받는다. 계정 비밀번호·서명 URL·원본 사진은 보고서에 넣지 않는다. 운영 상세 진입은 조회수 RPC를 유발할 수 있어 재현 수단으로 사용하지 않는다.

| 확인 순서 | 현재 구현에서 좁혀진 지점 | 같은 원인일 때만 적용할 최소안 |

## 4. 펫: 기존 자료를 잃지 않고 더 잘 찾게 한다

**등록과 수정의 공통 계약.** [등록](../../src/screens/Pets/PetCreateScreen.tsx)·[수정](../../src/screens/Pets/PetProfileEditScreen.tsx) 모두 대표 종과 빠른 세부 선택·직접 입력을 사용한다. 현재 카탈로그에는 대표 키 10종, 강아지·고양이 각각 믹스 포함 10개 세부 항목과 별칭이 있다. `species` 그룹·`speciesKey`·`speciesDetailKey`·`speciesDisplayName` 및 구 `breed`를 ‘종/품종 문자열 하나’로 합치지 않는다. 편집은 분류 미변경 시 구 값을 보존하는 경로가 있다. [구 클라이언트 쓰기 호환 SQL](../../supabase/migrations/20260917100000_pack04_legacy_species_write_compatibility.sql), [분류 테스트](../../__tests__/petSpeciesTaxonomy.test.ts)는 운영 데이터 분포 증거가 아니다.

1. 주 화면은 ‘강아지 / 고양이 / 그 외’로 찾고, ‘그 외’ 안에 토끼·조류 등 기존 세부 종을 보존한다. 기존 10종을 세 값으로 강등하지 않는다. 검색 시트는 탭 세 개 대신 선택 종 결과 + **‘다른 종도 검색’** 한 동작. 확장 시 두 종을 함께 표시하고 결과마다 종을 붙인다. 취소는 선택값을 바꾸지 않는다.
2. 이름·등록 별칭·안정 키를 미리 색인. 완성형과 분해 자모를 정규화하고 호환 초성과 대응시킨다. 정확한 이름·별칭 → 접두 → 이름/초성 포함 순, 동률은 기존 표시순·키. ‘ㅁㅌㅈ’·‘말티’·분해 자모 말티즈는 같은 항목, ‘ㅍ’은 푸들·페르시안 및 **중간에** ㅍ이 있는 항목도 포함, ‘코숏’은 코리안숏헤어. 종 제한과 확장 각각 시험. 기입 중 조합 미완성·공백·빈 결과도 이전 확정값을 바꾸지 않는다.
3. 다른 종의 결과는 ‘고양이로 바꾸고 페르시안을 선택할까요?’처럼 바뀔 두 값을 먼저 표시. 승인 시 종+세부값만 한 번에 교체, 취소는 이름·사진·날짜·추모·다른 초안까지 그대로. 현재 종 변경 함수가 세부값을 비우므로 **검색 중에는 그 함수를 호출하지 않는다**. 키보드 Back → 자판 닫기, 다음 Back → 시트 취소, 화면 Back → 기존 미저장 정책.
4. 믹스는 해당 종의 기존 믹스 키, ‘모름’은 품종 미지정(기존 스키마가 미입력과 구분 불가하면 그 한계를 안내), ‘목록에 없음’은 직접 입력·원문 보존. ‘그 외 동물’은 품종 모름과 다르다. 기존 미수록 값은 그대로 표시하고 다른 필드만 수정해도 손실되지 않아야 한다. 일괄 교정·마이그레이션 없음.
5. 첫 범위는 현재 로컬 목록. 확장은 출처·사용 조건·검수자·수록 기준·별칭 충돌·버전/폐기 키 대응표가 생긴 뒤. 리트리버처럼 여러 세부 종을 별칭으로 묶은 현행 분류는 검색 편의이지 공인 분류가 아니다. 목록이 커지면 미리 계산된 색인과 가시 행 렌더링으로 320 큰 글자·빠른 입력·스크롤 끝·초점 유지 확인. 모든 품종 보장은 제외.

**노출 정책 제안:** 미등록(조회 성공·0마리)은 등록 CTA, 데이터가 있는데 미선택이면 선택, 로딩은 중립 표시, 실패는 기존 자료 보존 또는 재시도. 기본 강아지로 대체하지 않는다. 살아 있는 선택 펫은 실제 대상 종과 검수된 공통 자료만 추천하며, 열람 가능한 가이드 목록을 추천 적격 목록과 혼동하지 않는다. ‘오늘의 팁’ 제거와 기존 추천 섹션은 별개. 추모 펫은 과거 건강·산책·사진·편지 열람 유지, 새 산책·미래 돌봄 유도는 숨기거나 추억 보기로 대체하는 안을 PO가 결정한다. 새 기록·과거 날짜 입력까지 일괄 금지하지 않는다. 서로 다른 종·추모 상태의 두 펫을 왕복할 때 이전 펫 추천의 늦은 응답이 새 화면을 덮지 않아야 한다. 부적합 노출은 화면·선택 상태·실제 콘텐츠 분류가 확인된 경우만 결함으로 승격한다.

## 5. 내 활동, 방문, 관계의 권한 계약

**먼저 본인에게만.** 커뮤니티에서 ‘내 글과 댓글’ → ‘글 / 댓글’ 두 탭. 댓글은 기본 시간순, ‘게시글별’로 바꾸면 현재 남아 있는 내 댓글이 달린 부모글을 중복 없이 찾는다. 마지막 댓글 삭제 후 해당 묶음은 사라진다. 선택 시 정상 원문/댓글 위치로 이동, Back은 탭·필터·위치 복원. 작성·수정·신고는 기존 화면 사용. [커뮤니티 스택](../../src/navigation/CommunityTabStackNavigator.tsx)과 [서비스](../../src/services/supabase/community.ts)의 기존 글·댓글을 정본으로 삼는다. 전체 피드를 내려받아 작성자로 필터링하거나 별도 활동 테이블에 이중 쓰지 않는다.

**서버 조회가 먼저다.** 실제 세션의 본인만 내역을 읽는다. 댓글과 부모 글 모두 현재 공개·삭제·제재·탈퇴 및 상호 차단 조건을 통과한 행에 대해서만 요약·개수·순번·첨부를 만든다. 로컬 [부모 가시성 정책](../../supabase/migrations/20260819110000_community_comment_parent_visibility_rls.sql)과 [가시 댓글 작성자 조회](../../supabase/migrations/20261109061317_community_visible_comment_author_nicknames.sql)를 출발점으로 삼되 새 집계가 자동 보호된다고 가정하지 않는다. 계정 범위 쿼리·안정 커서(시각+ID), 게시글별 묶음은 중복 제거 **후** 페이지 처리. 기존 계약으로 부족할 때만 최소 읽기 API 검토. 빈 결과·로딩·부분 페이지 오류·재시도·A→B 늦은 응답을 분리한다.

**방문은 별도 읽기 목적지 하나.** 글/댓글의 작성자 표시 → 공개 프로필 → 이후 같은 목적지에 공개한 펫 소개·선택 공유한 추억을 추가한다. 본인 관리와 방문자 보기의 조회 경로는 다르게 한다. 현행 글에는 작성자 ID·닉네임 스냅샷·펫 아바타가 있으며 제공자 계정 아바타는 의도적으로 표시하지 않는다. 펫 사진이나 닉네임을 계정 ID로 역추정하지 않는다. 본인도 ‘방문자 보기’에서는 실제 방문자용 필드만 읽는다. 본인 개인 홈을 mount한 뒤 섹션을 숨기는 방식 금지.

| 동작 | 도착점·유지할 상태 |
| --- | --- |
| 글/댓글 아바타·직접 링크 | 대상 ID는 조회 힌트일 뿐 권한이 아니다. 현재 세션·공개 동의·차단을 다시 검사. 열 수 없으면 존재 여부나 개수를 누설하지 않는 동일 안내. |
| 방문 중 펫 선택·공개 글 열기 | 방문 화면에만 공개 펫 ID 저장. 본인 전역 선택 불변. 허용 원문에서 Back은 해당 방문 탭과 위치로. |
| 상단/Android Back | 시트·키보드부터 닫고, 방문 화면에서는 진입한 원문·커뮤니티 위치로. 직접 링크로 이전 화면이 없으면 본인 홈. |
| ‘내 홈으로’·하단 홈 | 방문 상태 종료 → 본인 HomeTab, 유효한 원래 펫 선택. 없으면 본인 정상 선택 흐름. |
| 하단 타임라인·편지함·커뮤니티·전체메뉴 | 각 본인 탭으로 이동. [MoreTab은 탭 교체가 아니라 오버레이](../../src/navigation/AppTabsNavigator.tsx)다. 본인 계정 메뉴만 열고 닫으면 유효한 직전 화면, 철회됐으면 비공개 내용을 복원하지 않는다. |
| 앱 복원·계정 전환·철회 | 이전 방문자의 캐시로 먼저 그리지 않는다. 조회자·대상·공개 펫·세션 세대로 분리, 요청 취소 및 늦은 응답 폐기. 포커스/재접속 재인가 실패 시 목록·열린 상세·이미지 제거. 네트워크 오류를 공개 허용으로 해석하지 않는다. |

**공개 기본값은 제안, 미확정:** 로그인 사용자만, 기존/신규 모두 새 모아보기 기본 비공개. 초기에는 본인 동의 소개와 선택한 글 모음까지만. 댓글 모음은 동일 수준의 부모 가시성을 입증하고 별도 동의를 받은 뒤. 글·댓글 모음을 끄더라도 기존 커뮤니티 원문 자체가 비공개가 되는 것은 아니다. 설정 저장 실패 시 성공 표시 금지. 방문자 허용 목록에는 건강·지출·일정·알림·문의·계정·개인 편지가 들어가지 않는다. 사진도 **개별 공유** 대상만. 일촌도 원본 수정·삭제 권한 없음.

**일촌은 독립 후속.** 두 계정 쌍당 활성 관계 하나. 없음 → 대기(방향·요청 ID) → 수락 또는 종료. 수신자만 수락/거절, 발신자만 취소, 관계의 어느 쪽이나 해제, 차단은 모든 상태보다 우선. 자기 신청 거절, 같은 요청 재전송은 멱등, 교차 신청은 기존 받은 신청으로 안내하고 자동 친구 처리하지 않는다. 동시 수락/취소는 서버에서 하나만 확정하고 패자는 최신 상태 재조회. 응답 유실 뒤 새 요청을 두 번 만들지 않는다. 재신청 대기·빈도 제한, 신고 가능한 짧은 텍스트만(링크·첨부 제외), 차단 상대에게 메시지/거절 사유 노출 금지. 담당자·감사·처리/보관 책임 없이는 열지 않는다. 앱 내 요청함만 고려하고 OS 발송은 별도 승인.

**쓰기 단계는 관계 수락과 별개.** 현재 로그인 ∩ 양방향 차단 없음 ∩ 유효한 일촌 ∩ 대상 콘텐츠 열람 가능 ∩ 소유자의 해당 쓰기 허용을 읽기·작성·수정 시 서버에서 재검증한다. 댓글 작성자는 자기 글 관리, 공간 주인은 숨김/신고만. 좋아요 재시도는 중복 집계하지 않는다. [현재 편지함](../../src/screens/Guestbook/GuestbookScreen.tsx)은 선택한 펫의 private letters이며 방문자 방명록이 아니다. 후속 방명록은 별도 작성물로만 제공하거나 운영이 어렵다면 쓰기 자체를 미출시한다.

**회수 시험:** A 소유자·B 허용 방문자·C 차단 사용자로 직접 진입/열린 화면/목록 다음 페이지/첨부/쓰기 각각 확인. 해제 직후 관계 제한 콘텐츠·기존 댓글·방명록은 타인에게 기본 숨김 권장, 작성자는 원문 정보를 누설하지 않는 자기 삭제 경로를 유지. 재수락/차단 해제만으로 과거 공개를 복원하지 않는다. 공개 철회·탈퇴도 같은 가시성 재평가, 새 서명 발급 중지와 사용자별 캐시 폐기. 이미 전달된 파일·외부 사본까지 회수된다고 보장하지 않는다. 기존 URL 잔여 수명·백업/감사 보관·탈퇴 후 작성물 처리는 PO 정책 확정 전 공개 불가.

| 6 출시 후 선택 확장 | 일촌 상태와 운영 응답을 먼저, 성공하면 별도 승인으로 방명록/댓글/좋아요 중 하나씩. AI는 관계와 독립. | 채팅·전체 알림·소셜 그래프 일괄 공개·튜토리얼 복원 | 매우 큼. 동시 요청·차단·분쟁 처리와 운영 비용이 감당될 때만. AI는 FAQ 대비 해결률·실패율·사용량 예산을 평가한 뒤 진행/중지. |

**공통 UX 종료 기준:** 입력은 키보드가 떠도 현재 필드·다음 행동에 접근 가능, 첫 Back은 열린 내부 UI부터, 취소는 기존 초안·선택 유지. 긴 본문·긴 이름·목록 끝에서 버튼과 시스템바가 겹치지 않는다. 320 큰 글자와 해당 변경이 닿는 기존 D 조합만 표적 재검증. 느린 응답·재시도·계정 전환에서 거짓 성공/이전 사용자 자료를 보이지 않는다. 디자인이 바뀐 행은 과거 PASS 자동 승계 금지, 무관한 행 전수 재검증 금지.

**구독의 날짜 계약:** 실제 권리 출처 없으면 날짜 약속 없음. 미구독은 혜택/가입, 갱신 중은 확인된 다음 결제 예정일, 해지 예약은 이용 종료일과 잔여 이용, 만료는 만료 상태. 확인 실패는 ‘미구독’으로 바꾸지 않고 재확인 안내. 해지 확인창 취소는 변경 없음. 복원·환불·권리 복구는 서버/스토어의 확정 후에만 반영. 운영 차단과 현재 DEV 문구·스타일 보존, 명칭 변경과 그라데이션은 후순위.
