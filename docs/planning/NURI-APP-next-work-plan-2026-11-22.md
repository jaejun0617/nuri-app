# 누리 출시 전 잔여와 후속 제품 기획

2026-11-22 KST · Master 검토 정본 · **D만 기존 승인으로 진행. 이 문서의 제안은 실행·출시 승인이 아니다.**

**결론:** 출시 전에는 사용자가 로그인하고, 자기 펫을 선택하고, 기록과 문의를 읽고 쓰는 기존 흐름이 깨지는 문제를 먼저 닫는다. 품종을 찾거나 내 댓글로 돌아가는 개선은 이 목적에 맞지만, 다른 사람의 활동을 모아 보여주는 일은 별도의 공개 결정이다. 전면 리디자인·일촌·AI를 출시의 전제에서 뺀다. 요구 자체는 아래 대응표에 보존한다.

### UI-04. 날씨 상세: 같은 계절 풍경의 낮과 밤

첫 화면에서는 위치·현재 기온·날씨를 풍경 위에서 읽고, 아래로 내려가면 같은 하늘색 위에 놓인 패널에서 외출할 시간의 강수와 일주일 예보를 확인한다. 풍경만 보이는 별도 표지나 장식용 카드를 추가하지 않는다. 계절은 **풍경**, 낮·밤은 **빛**, 현재 날씨는 **하늘과 지면의 상태**를 결정한다. 자료가 없어도 쓸 수 있는 화면이어야 한다.

| 참고 영상에서 본 것 | 누리에 적용할 배경·패널 | 정보가 읽히는 방식 |
| --- | --- | --- |
| 낮 · 16초 · 1080×2340. 밝은 파란 하늘, 옅은 구름, 청록빛 수평선. 본문에서도 배경색이 이어지고 패널은 배경보다 한 톤 짙다. | 시안 시작색: 하늘 `#498FCC` → 수평선 `#78B8AB` → 본문 `#488DC2`. 글라스는 짙은 청록 `rgba(18,61,81,0.32)`부터 비교한다. | 밝은 구름 바로 위에 흰 글자를 놓지 않는다. 현재 기온·상태 뒤에만 색을 짙게 하고, 밝은 카드에서는 짙은 잉크색을 쓴다. |

위 색은 확정값이 아니라 시안 출발값이다. 넓은 패널과 부드러운 모서리를 유지하고 면의 밝기 차로 구분한다. 상단 안전영역부터 마지막 패널 아래까지 배경을 잇는다. 실제 이미지·패널을 합성하고 크롭한 결과를 기준으로 본문·보조 문구·날짜·단위·입력 안내는 4.5:1 이상, 의미 있는 아이콘·그래프·선택 표시는 인접 배경과 3:1 이상을 확인한다. TalkBack에서 요약 → 시간대 → 주간 순서와 그래프의 수치·단위 대체 설명을 확인하고 장식 풍경은 중복 낭독하지 않는다.

관측 자료가 갱신될 때는 날씨 코드·주야·관측 시점을 한 묶음으로 사용한다. 이전 응답의 주야와 새 응답의 코드를 섞지 않는다. 근거가 빠지면 중립 장면을 사용하고 오래된 값은 시점을 표시한다. 자산 매핑에는 그림에 이미 포함된 달·별·광원·눈·젖은 반사를 기록한다. 실제 상태와 충돌하면 레이어로 억지로 덮지 않고 중립 자산으로 대체한다.

**출시 경계:** 현재 날씨 정보 오류·읽기 불가·조작 불가만 기존 결함으로 선별한다. 새 계절 재질과 PO 시각 확정은 출시 게이트가 아니다. 품종 검색과 내 글·댓글 모음도 후속 편의다. 기존 등록·직접 입력·원문 접근에 결함이 있으면 그 결함만 출시 대상으로 본다.

## 3. ‘누리를 소개합니다’ 사진: 오류 지점을 먼저 나눈다

**판정: 증상 접수, 해당 게시물 원인·복구 여부 미확인.** 제목은 식별자가 아니다. 비공개로 게시물 식별자·첨부 순번, 목록/홈/상세/확대 중 진입점과 시각, 설치 후보·계정 역할·네트워크·재진입 변화, 가능하면 당시 오류 화면을 한 번에 받는다. 계정 비밀번호·서명 URL·원본 사진은 보고서에 넣지 않는다. 운영 상세 진입은 조회수 RPC를 유발할 수 있어 재현 수단으로 사용하지 않는다.

| 확인 순서 | 현재 구현에서 좁혀진 지점 | 같은 원인일 때만 적용할 최소안 |
| --- | --- | --- |
| 1. 어느 사진인가 | 일반 [목록 카드](../../src/screens/Community/components/PostCard.tsx)는 첨부 유무 아이콘, 펫 아바타는 별도 필드다. 홈 하이라이트는 별도 매핑이다. 상세는 본문을 네이티브 텍스트로 그리고 [첨부 갤러리](../../src/components/community/PostImageGallery.tsx)를 아래 붙인다. 이 갤러리의 일반 이미지는 확대 버튼이 아니다. | Markdown 이미지 파서·썸네일 생성기·확대 화면을 전제로 고치지 않는다. 실제 다른 뷰어에서만 실패했다면 해당 route를 먼저 식별. |
| 2. 작성·참조 | [제출](../../src/screens/Community/communityPostSubmit.shared.ts)은 업로드 경로를 받은 후 게시하며 부분 실패 정리 경로가 있다. [저장 서비스](../../src/services/supabase/storageCommunity.ts)는 사용자/게시글별 경로와 MIME·크기 검사를 사용. 로컬 [소유 검증 SQL](../../supabase/migrations/20261009153820_security_sec001_storage_ownership.sql)은 게시글과 참조 경로를 검사한다. | 업로드 완료·커밋/정리·파일 존재를 같은 ID로 비교. 한 글의 오참조면 원본·소유 관계를 확인한 그 행만 별도 복구 승인. 원본 없으면 복구 보장 불가. 업로드 구조 전체를 먼저 바꾸지 않는다. |
| 3. URL 해석 | [상세 서비스](../../src/services/supabase/community.ts)의 공개·active·미삭제 확인 후 `image_urls` 배열 우선, 배열이 아니면 `image_url`. 빈 배열 + 구 단일 경로 조합도 비교한다. HTTP(S)는 그대로, storage path는 1시간 URL 생성. 서명 실패는 null이며 일부 실패는 목록에서 걸러질 수 있다. | 권한 거절·만료·유실을 구분. 허용된 참조만 **현재 권한으로** 다시 해석. 모든 슬롯 누락과 일부 누락을 분리하고 순번 보존. 직접 원문 조회로 차단 우회 금지. |

URL이 있으면 갤러리가 로딩·재시도를 제공하지만 같은 URI를 다시 여는 방식이다. 디코딩 비율 오류도 실패 표시가 된다. | 정상 참조라면 요청 유무·상태·MIME·바이트 길이·실제 디코딩/메모리·앱 캐시와 이전 세션 캐시를 분리. 같은 URI 재요청, 새 서명 발급, 손상 파일 복구는 다른 조치. 실패가 확정된 가장 좁은 층에서만 수정. |

**종료 시험(후속):** 같은 후보 조건에서 합성 재현 1건 + 같은 방식 정상 대조 1건 + 권한 없는 계정 1건. 본문과 Back은 사진 실패 중에도 동작하고, 허용된 사용자의 명시적 재시도는 실패 슬롯만 복구하며 중복 조회수·무한 요청을 만들지 않아야 한다. 원래 실패가 재현되지 않으면 ‘미재현’, 단건만 복구하면 ‘자료 복구’, 회귀 사례까지 통과해야 ‘해당 원인 해결’로 기록한다. 로그는 실패 단계·비밀 아닌 상관 ID만. 버킷 공개·RLS 완화·운영 사진 복제는 제외.

### 3-A. 11/23 앞당겨 확인한 이미지 진단

**판정: 로컬 코드·합성 진단 완료, ‘누리를 소개합니다’ 원인과 수정 수락은 보류.** 일반 피드 카드의 ‘사진’ 표시는 첨부 개수/존재 아이콘이지 사진 다운로드 성공 표시가 아니다. 일반 상세에서는 네이티브 본문과 첨부 갤러리가 별도다. 일반 상세 갤러리에는 확대 조작이 없어 확대 실패가 제보였다면 다른 진입점을 먼저 확인한다. 제목 문자열로 동일 게시물·계정·기기·후보를 특정할 별도 증거는 확보하지 못했다.

| 합성 입력과 코드 근거 | 확인 결과 | 원인이 일치할 때만 검토할 최소 수정 |
| --- | --- | --- |
| 구형 단일 경로, 사진 배열이 `null`인 정상 대조와 `[]`인 경우 | 정상 대조는 1시간 다운로드 주소를 받아 표시로 전달한다. 빈 배열인 대조는 단일 경로가 남았는데도 서명을 호출하지 않고, 본문과 실패 표시용 `hasImage`만 남는다. | 빈 배열이 과거 데이터인지 사용자가 의도해 사진을 모두 제거한 결과인지 계약부터 구분. 삭제 사진이 되살아날 수 있어 무조건 단일 경로로 대체하지 않는다. |
| 새 글은 배열·단일 경로를 함께 저장, 사진 수정 흐름은 단일 경로만 덮어씀 | 합성 행에서 수정 이후 배열이 그대로면 상세는 새 단일 경로가 아니라 이전 배열을 읽는다. 수정 코드가 이전 대표 파일의 정리를 호출하는 것도 확인했다. 해당 게시글이 이 경로를 거쳤거나 운영에서 배열 동기화가 없다는 증거는 아니다. | 실제 수정 전후 계약 확인 후 대표 경로와 배열을 같은 저장 결과에서 갱신. 텍스트만 편집하면 첨부 배열 보존. 이전 파일은 참조가 끊긴 저장 성공 후에만 정리. |
| 두 경로 중 첫 주소 서명에 실패하도록 구성 | 본문은 남지만 서명 실패 슬롯이 목록에서 빠져 두 번째가 첫 번째로 표시된다. 전부 실패해 주소가 없으면 상세의 문구에 재시도 버튼이 없다. 거절·유실·만료는 이 로컬 함수에서 모두 빈 결과로 취급될 수 있다. | 실제 실패가 주소 발급 전이면 슬롯과 실패 단계부터 유지하고, 현재 권한으로 실패한 슬롯만 다시 발급. 실패 요약을 모두 실제 파일 유실로 기록하지 않는다. |
| 사진이 완성된 HTTP(S) 주소로 저장됐거나, 발급 후 네이티브 Image에서 실패 | 저장된 절대 주소는 서명을 새로 하지 않고 전달한다. 갤러리 재시도는 같은 URI의 Image를 다시 열며, 서명 갱신은 하지 않는다. 기존 테스트로 개별 재시도 UI와 비정상 이미지 크기 처리를 대조했다. | 일시적 다운로드 실패와 만료를 분리. 만료는 승인된 Storage 원본 경로가 있을 때만 새 주소를 발급한다. 네트워크/형식/MIME·파일 존재 여부는 당시 자료로 확인하며 캐시 삭제만으로 원인 해결이라 하지 않는다. |

- 보호 상세 RPC를 포함한 실제 앱 매핑과 갱신 payload를 모의 응답으로 시험했다. 연관 Jest 5묶음 55개(이번 진단 대조 5개 포함)가 통과한 것은 **현재 동작을 확인한 것**이며, 제보 사건을 수정했다는 뜻이 아니다. 원본 사진 다운로드, 운영 조회수 RPC, 운영 DB·Storage 조회/변경·삭제, 권한 변경은 하지 않았다.
- **다음 한 입력:** 해당 글 공유 링크 또는 비공개 게시글 ID와 실패한 사진 순번. 가능한 범위에서 실패 화면(목록·상세·별도 확대), 발생 시각, 당시 앱 버전과 계정 역할을 원시 비밀 없이 함께 받는다. 링크 수신 후에도 운영 화면을 무작정 열지 않고, 승인된 읽기 전용 자료나 익명화된 오류 상태로 업로드 완료 → 참조 → 서명 → 다운로드·디코딩 순서를 좁힌다. 원본이 없으면 작성자 승인 원본 또는 백업 없이는 복구를 보장하지 않는다.
- **완료 조건:** 제보와 동일 원인 재현 → 최소 수정 → 정상 대조·권한 없음·동일 파일 재시도 회귀 확인. 본문·다른 첨부는 유지하고 실패 슬롯만 명시 재시도로 복구하며, 중복 요청·오류 단계 감지만 최소 검증한다. 행별 파일 경로·서명 토큰은 기록하거나 외부에 전달하지 않는다. 이번에는 제품 수정과 실제 운영 수락을 시작하지 않았다.

## 3-B. 커뮤니티 댓글·답글 작성 개선 기획서

**2026-11-23 · Master 기획 정본 · 구현·검증 범위는 §6.** 목표는 댓글을 읽던 사람이 답글 대상을 놓치지 않고 한 번에 작성하는 것이다. **대상은 목록에서 고르고, 글은 하단 입력창 하나에서 쓴다.** 키보드에 가리지 않는 것이 첫 번째 완료 조건이다. 전송 버튼과 좋아요의 외관은 그다음이다.

#### 1. 문제와 근거

| PO 캡처에서 확인한 상태 | 확인하지 못한 것 |
| --- | --- |
| A32 게시글 상세, 키보드 닫힘: 일반 댓글 입력창과 시스템 탐색바 사이에 큰 빈 공간이 보인다. | 처음부터 비었는지, 키보드를 닫은 뒤 남았는지. |
| 커뮤니티 게시글에서 답글 작성, 키보드 열림: 대상 안내와 빈 입력란의 커서는 보이지만 키보드 상단 도구막대가 입력란 하단과 원형 전송 버튼 하단을 덮는다. | 이 캡처의 기종·배율·설치본, 실제 전송 가능 여부, 앞 현상과 같은 원인인지. |

- **영상에서 본 차이:** ‘마미톡 답글달기’는 약 3초에 댓글 화면으로 넘어가며 답글 대상과 키보드 위 입력창이 함께 나타난다. 목록을 움직여도 작성 위치는 유지된다. ‘누리앱답글달기’는 약 2초에 입력창이 댓글 사이에 삽입돼 뒤의 댓글을 밀고, 이어쓰기 동작 후 댓글 화면에서도 목록 안에 남는다. 참조할 것은 한 번의 진입과 고정된 작성 위치다. 타사 말풍선·색·이미지 첨부 기능은 가져오지 않는다.
- **PO의 시각 피드백:** 한 줄 입력창이 두껍고 빈 상태의 회색 화살표가 자리를 차지한다. 게시글 사진과 좋아요, 댓글 헤더 사이 여백도 넓어 보인다. 이는 위 두 배치 결함과 별개인 개선 요구다.
- **현재 코드 근거:** [상세·댓글 공용 화면](../../src/screens/Community/CommunityDiscussionContent.tsx)은 일반 댓글과 목록 속 답글의 배치를 나눈다. [입력 컴포넌트](../../src/screens/Community/components/CommunityCommentComposer.tsx)는 공백만 있으면 전송을 막지만 버튼 자체는 그린다. [스타일](../../src/screens/Community/CommunityDetailScreen.styles.ts)은 한 줄 필드 최소 52dp, 안쪽 입력 최소 44dp에 바깥 여백이 별도로 있다. 이 구조만으로 키보드 가림의 원인을 확정하지 않는다.

#### 2. 목표 사용 흐름

| 사용자 행동 | 화면의 반응 | 잃지 않아야 할 것 |
| --- | --- | --- |
| 게시글에서 일반 댓글 입력 | 현재 화면의 하단 입력창을 사용한다. 답글 대상 줄은 없다. | 불필요한 화면 이동이나 답글 대상 지정 없음. |
| 게시글에서 ‘답글쓰기’ | 기존 댓글 전체 화면을 **한 번만** 열고 대상이 있는 묶음을 펼친다. 화면이 준비되면 선택한 댓글을 보이는 범위로 옮기고 하단 입력창에 초점과 키보드를 준다. ‘작성 중인 답글 이어쓰기’를 다시 누를 필요가 없다. | 같은 게시글·같은 댓글·기존 정렬·원래 게시글 복귀 위치. 로딩 중 다른 대상을 택하거나 뒤로 가면 이전 초점 요청은 취소한다. |
| 댓글 전체 화면에서 ‘답글쓰기’ | 화면을 다시 열지 않는다. 선택한 댓글을 짧게 강조하고 하단에 ‘○○님 댓글에 답글’ 또는 ‘○○님에게 답글’과 취소를 표시한다. 강조색 없이도 문구로 구분한다. | 원댓글에 달기와 특정 답글에 답장하기를 구분한다. 목록을 스크롤해도 수신 대상과 입력창 위치는 그대로다. |
| 다른 대상 선택·답글 취소 | 빈 초안은 바로 전환한다. 글이 있으면 누리 확인창에서 ‘계속 작성’이 기본이다. 명시적으로 ‘초안 버리고 전환’ 또는 ‘초안 버리고 취소’를 선택해야만 폐기한다. | 기존 문구를 새 상대나 일반 댓글로 몰래 옮기지 않는다. 대상이 삭제·차단되면 전송을 막고 이유를 안내하며, 초안을 자동 폐기하거나 일반 댓글로 대신 보내지 않는다. |
| 키보드 닫기·화면 복귀 | 키보드가 열린 상태의 첫 시스템 Back은 키보드만 닫는다. 다음 Back과 상단 Back은 원래 진입 화면으로 돌아간다. | 같은 게시글의 상세↔댓글 사이에는 대상·초안·커서·각 목록의 복귀 위치를 보존한다. 게시글을 완전히 떠날 때만 미전송 초안 폐기 확인. 다른 게시글·계정에 이전 초안을 표시하지 않는다. |

#### 3. 입력창·전송·좋아요 사양

| 요소 | 적용안과 완료 기준 |
| --- | --- |
| 하단 배치 | 키보드가 닫히면 입력창 바깥 배경이 앱의 하단 사용 영역에 닿고 시스템 탐색 영역은 침범하지 않는다. 열리면 도구막대를 포함한 **키보드의 실제 윗변** 바로 위에 놓인다. 안전영역·키보드·숨겨진 하단 탭 높이를 두 번 빼지 않는다. 목록만 스크롤하며 마지막 댓글도 입력창 뒤에 숨지 않는다. |
| 크기·재질 | 한 줄 필드는 **약 48dp를 시안 시작값**으로 삼고 바깥 상하 여백부터 줄인다. 기존 누리 입력 표면과 글자 정책을 따른다. 여러 줄이면 높이가 늘고 기존 상한부터 입력 안에서 스크롤한다. 한글 조합·긴 문장·큰 글자에서 마지막 줄과 커서가 보여야 한다. 48dp에 맞추려고 글자를 줄이지 않는다. |
| 빈 값 → 입력 | 공백·줄바꿈뿐이면 화살표를 표시하지 않고 터치·낭독 대상에서도 뺀다. 보낼 글자가 생기면 [공통 CTA](../../src/app/ui/CtaButton.tsx)의 **라벤더 배경 + 흰 위쪽 화살표**를 사용한다. 오른쪽 영역의 폭을 안정적으로 유지해 표시·숨김 때 줄바꿈이나 커서가 튀지 않게 한다. 시각적 원과 별개로 터치 목표는 48×48dp 이상, 낭독 이름은 ‘댓글 전송’ 또는 ‘답글 전송’이다. |
| 전송 중·성공·실패 | 전송 중에는 같은 자리에 진행 표시, 연속 탭은 한 번만 처리한다. 성공이 확인된 뒤에만 초안을 비우고 해당 묶음의 새 댓글을 확인할 수 있게 한다. 명시적 실패는 대상·입력값을 유지하고 이유와 재시도를 제공한다. 결과가 불분명할 때는 자동 재전송하지 않는다. 기존 로그인·길이 제한(500자)·신고/차단 정책은 유지한다. |
| 게시글 좋아요 | 사진 아래 여백, 좋아요 행의 위아래 여백, 댓글 헤더 여백을 함께 보고 겹치는 간격만 줄인다. 하트와 ‘좋아요 N’, 선택 상태는 유지한다. 외곽선 안쪽 좌우 여백을 먼저 줄이고, 실제 누르는 영역이나 ‘신고하기’와의 간격을 희생하지 않는다. 사진 없는 글, 내 글, 신고 버튼이 있는 타인 글, 여러 자리 숫자에서 비교한다. 댓글별 좋아요의 배치나 집계 계약은 변경하지 않는다. |

#### 4. 수정 순서와 보호할 계약

1. **수정 전 기준 확보.** 기존 격리 게시글의 위·아래쪽 댓글에서 첫 진입 → 입력 → 키보드 닫기 → 다시 열기를 관측한다. 설치 후보, 실제 앱 창 크기·밀도·글자 배율·탐색 방식, 키보드와 도구막대 상태를 함께 남긴다. 앱 루트·댓글 영역·입력창 외곽·전송 터치 영역·키보드 상단을 같은 창 좌표계로 비교한다. 루트부터 짧은지, 댓글 영역만 줄었는지, 닫은 뒤 이전 높이가 남는지 구분한다. 기기별 고정 오프셋을 넣지 않는다.
2. **하단 작성 위치 통일.** 기존 화면·[게시글별 작성 세션](../../src/screens/Community/discussionSession.ts)을 재사용한다. 목록 안에는 입력창 대신 선택 표시만 두고, 현재 활성 화면에서만 입력창 하나가 초점을 갖는다. 키보드 겹침은 한 곳에서만 보정한다. 목록의 가상화·페이징·접힘 상태를 유지하고 키 입력마다 전체 목록을 다시 그리지 않는다.
3. **대상·쓰기 계약 회귀 방지.** [기존 대상 매핑](../../src/screens/Community/utils/commentHelpers.ts)을 유지한다. 일반 댓글은 부모·답장 대상 모두 없음, 원댓글에 다는 답글은 부모만 설정, 특정 답글에 대한 답장은 원래 부모와 선택한 답글 ID를 함께 유지한다. 대상 미확보를 일반 댓글로 바꾸지 않는다. 이 디자인 때문에 DB·권한·알림·조회수 계약을 바꾸지 않는다.
4. **시각 개선 후 영향 확인.** 전송 상태, 입력창 높이, 좋아요 여백을 적용한 최종 화면에서 같은 가림·공백 조건을 다시 확인한다. 공통 원인이 발견된 경우에만 **1:1 문의방 → 편지 입력 → 커뮤니티 글 작성 → 기록·일정 편집** 순으로 같은 하단 배치를 쓰는 상태를 선별한다. 다른 화면 전체를 선제 수정하지 않는다.

## 4. 펫: 기존 자료를 잃지 않고 더 잘 찾게 한다

**등록과 수정의 공통 계약.** [등록](../../src/screens/Pets/PetCreateScreen.tsx)·[수정](../../src/screens/Pets/PetProfileEditScreen.tsx) 모두 대표 종과 빠른 세부 선택·직접 입력을 사용한다. 현재 카탈로그에는 대표 키 10종, 강아지·고양이 각각 믹스 포함 10개 세부 항목과 별칭이 있다. `species` 그룹·`speciesKey`·`speciesDetailKey`·`speciesDisplayName` 및 구 `breed`를 ‘종/품종 문자열 하나’로 합치지 않는다. 편집은 분류 미변경 시 구 값을 보존하는 경로가 있다. [구 클라이언트 쓰기 호환 SQL](../../supabase/migrations/20260917100000_pack04_legacy_species_write_compatibility.sql), [분류 테스트](../../__tests__/petSpeciesTaxonomy.test.ts)는 운영 데이터 분포 증거가 아니다.

1. 주 화면은 ‘강아지 / 고양이 / 그 외’로 찾고, ‘그 외’ 안에 토끼·조류 등 기존 세부 종을 보존한다. 기존 10종을 세 값으로 강등하지 않는다. 검색 시트는 탭 세 개 대신 선택 종 결과 + **‘다른 종도 검색’** 한 동작. 확장 시 두 종을 함께 표시하고 결과마다 종을 붙인다. 취소는 선택값을 바꾸지 않는다.
2. 이름·등록 별칭·안정 키를 미리 색인. 완성형과 분해 자모를 정규화하고 호환 초성과 대응시킨다. 정확한 이름·별칭 → 접두 → 이름/초성 포함 순, 동률은 기존 표시순·키. ‘ㅁㅌㅈ’·‘말티’·분해 자모 말티즈는 같은 항목, ‘ㅍ’은 푸들·페르시안 및 **중간에** ㅍ이 있는 항목도 포함, ‘코숏’은 코리안숏헤어. 종 제한과 확장 각각 시험. 기입 중 조합 미완성·공백·빈 결과도 이전 확정값을 바꾸지 않는다.
3. 다른 종의 결과는 ‘고양이로 바꾸고 페르시안을 선택할까요?’처럼 바뀔 두 값을 먼저 표시. 승인 시 종+세부값만 한 번에 교체, 취소는 이름·사진·날짜·추모·다른 초안까지 그대로. 현재 종 변경 함수가 세부값을 비우므로 **검색 중에는 그 함수를 호출하지 않는다**. 키보드 Back → 자판 닫기, 다음 Back → 시트 취소, 화면 Back → 기존 미저장 정책.
4. 믹스는 해당 종의 기존 믹스 키, ‘모름’은 품종 미지정(기존 스키마가 미입력과 구분 불가하면 그 한계를 안내), ‘목록에 없음’은 직접 입력·원문 보존. ‘그 외 동물’은 품종 모름과 다르다. 기존 미수록 값은 그대로 표시하고 다른 필드만 수정해도 손실되지 않아야 한다. 일괄 교정·마이그레이션 없음.
5. 첫 범위는 현재 로컬 목록. 확장은 출처·사용 조건·검수자·수록 기준·별칭 충돌·버전/폐기 키 대응표가 생긴 뒤. 리트리버처럼 여러 세부 종을 별칭으로 묶은 현행 분류는 검색 편의이지 공인 분류가 아니다. 목록이 커지면 미리 계산된 색인과 가시 행 렌더링으로 320 큰 글자·빠른 입력·스크롤 끝·초점 유지 확인. 모든 품종 보장은 제외.

**노출 정책 제안:** 미등록(조회 성공·0마리)은 등록 CTA, 데이터가 있는데 미선택이면 선택, 로딩은 중립 표시, 실패는 기존 자료 보존 또는 재시도. 기본 강아지로 대체하지 않는다. 살아 있는 선택 펫은 실제 대상 종과 검수된 공통 자료만 추천하며, 열람 가능한 가이드 목록을 추천 적격 목록과 혼동하지 않는다. ‘오늘의 팁’ 제거와 기존 추천 섹션은 별개. 추모 펫은 과거 건강·산책·사진·편지 열람 유지, 새 산책·미래 돌봄 유도는 숨기거나 추억 보기로 대체하는 안을 PO가 결정한다. 새 기록·과거 날짜 입력까지 일괄 금지하지 않는다. 서로 다른 종·추모 상태의 두 펫을 왕복할 때 이전 펫 추천의 늦은 응답이 새 화면을 덮지 않아야 한다. 부적합 노출은 화면·선택 상태·실제 콘텐츠 분류가 확인된 경우만 결함으로 승격한다.

## 5. 내 활동, 방문, 관계의 권한 계약

**먼저 본인에게만.** 커뮤니티에서 ‘내 글과 댓글’ → ‘글 / 댓글’ 두 탭. 댓글은 기본 시간순, ‘게시글별’로 바꾸면 현재 남아 있는 내 댓글이 달린 부모글을 중복 없이 찾는다. 마지막 댓글 삭제 후 해당 묶음은 사라진다. 선택 시 정상 원문/댓글 위치로 이동, Back은 탭·필터·위치 복원. 작성·수정·신고는 기존 화면 사용. [커뮤니티 스택](../../src/navigation/CommunityTabStackNavigator.tsx)과 [서비스](../../src/services/supabase/community.ts)의 기존 글·댓글을 정본으로 삼는다. 전체 피드를 내려받아 작성자로 필터링하거나 별도 활동 테이블에 이중 쓰지 않는다.

**서버 조회가 먼저다.** 실제 세션의 본인만 내역을 읽는다. 댓글과 부모 글 모두 현재 공개·삭제·제재·탈퇴 및 상호 차단 조건을 통과한 행에 대해서만 요약·개수·순번·첨부를 만든다. 로컬 [부모 가시성 정책](../../supabase/migrations/20260819110000_community_comment_parent_visibility_rls.sql)과 [가시 댓글 작성자 조회](../../supabase/migrations/20261109061317_community_visible_comment_author_nicknames.sql)를 출발점으로 삼되 새 집계가 자동 보호된다고 가정하지 않는다. 계정 범위 쿼리·안정 커서(시각+ID), 게시글별 묶음은 중복 제거 **후** 페이지 처리. 기존 계약으로 부족할 때만 최소 읽기 API 검토. 빈 결과·로딩·부분 페이지 오류·재시도·A→B 늦은 응답을 분리한다.

**방문은 별도 읽기 목적지 하나.** 글/댓글의 작성자 표시 → 공개 프로필 → 이후 같은 목적지에 공개한 펫 소개·선택 공유한 추억을 추가한다. 본인 관리와 방문자 보기의 조회 경로는 다르게 한다. 현행 글에는 작성자 ID·닉네임 스냅샷·펫 아바타가 있으며 제공자 계정 아바타는 의도적으로 표시하지 않는다. 펫 사진이나 닉네임을 계정 ID로 역추정하지 않는다. 본인도 ‘방문자 보기’에서는 실제 방문자용 필드만 읽는다. 본인 개인 홈을 mount한 뒤 섹션을 숨기는 방식 금지.

| 동작 | 도착점·유지할 상태 |
| --- | --- |
| 글/댓글 아바타·직접 링크 | 대상 ID는 조회 힌트일 뿐 권한이 아니다. 현재 세션·공개 동의·차단을 다시 검사. 열 수 없으면 존재 여부나 개수를 누설하지 않는 동일 안내. |
| 방문 중 펫 선택·공개 글 열기 | 방문 화면에만 공개 펫 ID 저장. 본인 전역 선택 불변. 허용 원문에서 Back은 해당 방문 탭과 위치로. |
| 상단/Android Back | 시트·키보드부터 닫고, 방문 화면에서는 진입한 원문·커뮤니티 위치로. 직접 링크로 이전 화면이 없으면 본인 홈. |
| ‘내 홈으로’·하단 홈 | 방문 상태 종료 → 본인 HomeTab, 유효한 원래 펫 선택. 없으면 본인 정상 선택 흐름. |

**공개 기본값은 제안, 미확정:** 로그인 사용자만, 기존/신규 모두 새 모아보기 기본 비공개. 초기에는 본인 동의 소개와 선택한 글 모음까지만. 댓글 모음은 동일 수준의 부모 가시성을 입증하고 별도 동의를 받은 뒤. 글·댓글 모음을 끄더라도 기존 커뮤니티 원문 자체가 비공개가 되는 것은 아니다. 설정 저장 실패 시 성공 표시 금지. 방문자 허용 목록에는 건강·지출·일정·알림·문의·계정·개인 편지가 들어가지 않는다. 사진도 **개별 공유** 대상만. 일촌도 원본 수정·삭제 권한 없음.

**일촌은 독립 후속.** 두 계정 쌍당 활성 관계 하나. 없음 → 대기(방향·요청 ID) → 수락 또는 종료. 수신자만 수락/거절, 발신자만 취소, 관계의 어느 쪽이나 해제, 차단은 모든 상태보다 우선. 자기 신청 거절, 같은 요청 재전송은 멱등, 교차 신청은 기존 받은 신청으로 안내하고 자동 친구 처리하지 않는다. 동시 수락/취소는 서버에서 하나만 확정하고 패자는 최신 상태 재조회. 응답 유실 뒤 새 요청을 두 번 만들지 않는다. 재신청 대기·빈도 제한, 신고 가능한 짧은 텍스트만(링크·첨부 제외), 차단 상대에게 메시지/거절 사유 노출 금지. 담당자·감사·처리/보관 책임 없이는 열지 않는다. 앱 내 요청함만 고려하고 OS 발송은 별도 승인.

**쓰기 단계는 관계 수락과 별개.** 현재 로그인 ∩ 양방향 차단 없음 ∩ 유효한 일촌 ∩ 대상 콘텐츠 열람 가능 ∩ 소유자의 해당 쓰기 허용을 읽기·작성·수정 시 서버에서 재검증한다. 댓글 작성자는 자기 글 관리, 공간 주인은 숨김/신고만. 좋아요 재시도는 중복 집계하지 않는다. [현재 편지함](../../src/screens/Guestbook/GuestbookScreen.tsx)은 선택한 펫의 private letters이며 방문자 방명록이 아니다. 후속 방명록은 별도 작성물로만 제공하거나 운영이 어렵다면 쓰기 자체를 미출시한다.

**회수 시험:** A 소유자·B 허용 방문자·C 차단 사용자로 직접 진입/열린 화면/목록 다음 페이지/첨부/쓰기 각각 확인. 해제 직후 관계 제한 콘텐츠·기존 댓글·방명록은 타인에게 기본 숨김 권장, 작성자는 원문 정보를 누설하지 않는 자기 삭제 경로를 유지. 재수락/차단 해제만으로 과거 공개를 복원하지 않는다. 공개 철회·탈퇴도 같은 가시성 재평가, 새 서명 발급 중지와 사용자별 캐시 폐기. 이미 전달된 파일·외부 사본까지 회수된다고 보장하지 않는다. 기존 URL 잔여 수명·백업/감사 보관·탈퇴 후 작성물 처리는 PO 정책 확정 전 공개 불가.

**공통 UX 종료 기준:** 입력은 키보드가 떠도 현재 필드·다음 행동에 접근 가능, 첫 Back은 열린 내부 UI부터, 취소는 기존 초안·선택 유지. 긴 본문·긴 이름·목록 끝에서 버튼과 시스템바가 겹치지 않는다. 320 큰 글자와 해당 변경이 닿는 기존 D 조합만 표적 재검증. 느린 응답·재시도·계정 전환에서 거짓 성공/이전 사용자 자료를 보이지 않는다. 디자인이 바뀐 행은 과거 PASS 자동 승계 금지, 무관한 행 전수 재검증 금지.

**구독의 날짜 계약:** 실제 권리 출처 없으면 날짜 약속 없음. 미구독은 혜택/가입, 갱신 중은 확인된 다음 결제 예정일, 해지 예약은 이용 종료일과 잔여 이용, 만료는 만료 상태. 확인 실패는 ‘미구독’으로 바꾸지 않고 재확인 안내. 해지 확인창 취소는 변경 없음. 복원·환불·권리 복구는 서버/스토어의 확정 후에만 반영. 운영 차단과 현재 DEV 문구·스타일 보존, 명칭 변경과 그라데이션은 후순위.
