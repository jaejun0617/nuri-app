# NURI 수익화·구독·광고 검토

기준일: 2026-07-22
상태: 제안·검토 단계, 결제/광고 SDK 미구현

## 결론

NURI에 바로 `1개월 무료 후 모든 기능을 월 3,300원`으로 전환하는 방식은 권장하지 않는다. NURI는 반려동물 기록과 커뮤니티의 초기 신뢰·습관 형성이 핵심이라, 한 달 동안 무료로 핵심 가치를 모두 제공한 뒤 갑자기 전체 잠금을 걸면 전환 직전 이탈과 반감이 커질 가능성이 높다.

권장안은 다음과 같다.

- 핵심 기록, 커뮤니티, 기본 날씨, 동물병원 조회는 계속 무료로 유지한다.
- `NURI Plus`를 별도 구독으로 만들고, 반복 가치가 분명한 기능에만 구독을 적용한다.
- Plus 혜택 후보는 광고 제거, 기록·사진 보관 확장, 고급 건강 요약, 내보내기·백업, 여러 보호자 공유처럼 운영비와 연결되는 기능으로 제한한다.
- 초기에는 7일 체험 또는 제한된 얼리 액세스 30일 혜택을 A/B 테스트하고, 1개월 무료를 전면 정책으로 고정하지 않는다.
- 월 3,300원은 진입 가격으로는 적절하지만 단독으로 사업을 지탱할 가격은 아니다. 연간 플랜은 충분한 잔존 가치와 환불 정책을 확인한 뒤 검토한다.

## 월 3,300원 경제성

월 매출은 `유료 구독자 수 × 3,300원`이다. Google Play 수수료, 부가세·세금, 환불·미수금·고객지원·서버비를 차감하기 전 금액이다. Google의 공식 안내는 자동 갱신 구독에 일반적으로 15% 수수료가 적용되는 구조를 설명하지만, 한국의 수수료 변경 일정과 개발자 계정 적용 조건은 Play Console에서 실제 계약을 확인해야 한다. 플랫폼 수수료만 15%로 단순 계산해도 1명당 약 2,805원이며, 실제 정산액은 더 낮아질 수 있다.

예시:

- 유료 100명: 월 총액 330,000원, 플랫폼 수수료만 반영한 단순 잔액 약 280,500원.
- 유료 300명: 월 총액 990,000원, 플랫폼 수수료만 반영한 단순 잔액 약 841,500원.
- 월 운영비가 500,000원이라면 세금·환불·지원비를 제외하고도 약 179명의 유료 구독자가 필요하다.

따라서 가격 자체보다 `무료 사용자 중 실제로 반복 사용하고 결제할 사용자의 비율`이 핵심이다. 먼저 다음 지표를 수집해야 한다.

- 가입 후 펫 등록 완료율
- 첫 기록 작성률
- 7일·30일 유지율
- 월간 활성 사용자와 주간 활성 사용자
- Plus 소개 화면 조회 대비 결제 시작률
- 체험 종료 후 유료 전환율
- 결제 후 30일 유지율·취소율
- 광고 노출 후 이탈률
- 유료 사용자의 광고 제거 체감과 고객 문의

## 구독 구현 시 필수 구조

1. Google Play Console에 subscription product와 base plan/offer를 만든다.
2. 앱은 Play Billing 구매 흐름만 시작하고, 구매 결과만 서버로 전달한다.
3. Supabase Edge Function 또는 별도 server runtime에서 Google Play Developer API로 구매 토큰을 검증한다.
4. `subscription_entitlements` projection을 사용자별로 유지하고, 상태는 active·grace·paused·canceled·expired·revoked처럼 명시적인 값으로 관리한다.
5. 갱신, 환불, 취소, 결제 유예, 기기 변경을 서버 이벤트 또는 주기 검증으로 반영한다.
6. 앱은 서버 entitlement만 읽고 프리미엄 UI를 열어야 한다. 클라이언트의 `결제 성공` flag를 권한 source로 사용하지 않는다.
7. 구매·검증·갱신·취소·환불·복구는 audit와 고객지원용 상태 이력을 남긴다.
8. 결제 기능을 넣기 전 개인정보처리방침, 이용약관, 환불·해지 안내, Play Console 상품 문구를 함께 준비한다.

이번 턴에는 위 계약과 테이블을 만들지 않았다. Play Console 상품과 실제 결제 계정이 확정된 뒤 additive migration과 서버 검증부터 구현한다.

## 광고를 붙이는 방법

### 1. AdMob 계정과 앱 등록

- AdMob에서 Android 앱과 App ID를 만든다.
- 광고 유형별 ad unit을 만든다.
- 개발 중에는 반드시 Google 테스트 App ID/ad unit을 사용하고, 자체 광고를 클릭하지 않는다.
- 실제 App ID와 ad unit은 소스 코드에 평문으로 직접 넣지 말고 release 환경 설정으로 관리한다.

### 2. SDK와 동의

- React Native용 Google Mobile Ads adapter를 검토하고 Android native build에 연결한다.
- 앱 시작 시 Mobile Ads SDK를 초기화하되, 필요한 사용자 동의 확인 전에 광고를 요청하지 않는다.
- UMP SDK로 동의 정보를 갱신하고, 사용자가 개인정보 광고 설정을 다시 열 수 있는 진입점을 제공한다.
- 광고 도입 후 Play Console Data safety와 개인정보처리방침을 갱신한다.

### 3. app-ads.txt

- 개발자 웹사이트를 Play Store 앱 정보에 등록한다.
- 웹사이트 루트의 `/app-ads.txt`에 AdMob에서 발급한 authorized seller 행을 게시한다.
- HTTP/HTTPS 접근, 200 응답, robots 차단 여부를 확인한다.
- AdMob이 crawl·검증할 때까지 시간이 걸리므로 출시 직전에 처리하지 않는다.

### 4. NURI에 권장하는 광고 위치

허용 후보:

- 무료 사용자의 커뮤니티 목록 중간에 한정된 native/banner 1개
- 산책 검색 결과 하단의 작은 banner
- 광고 제거를 구독 혜택으로 제공

배치 금지:

- 홈 날씨 메인 카드와 온도 안전 안내 바로 옆
- 건강 기록 작성·상세와 저장 CTA 주변
- 동물병원 전화·길찾기 CTA 주변
- 편지·추억·무지개다리 관련 감성 화면
- 댓글 입력·신고·모더레이션 흐름
- 앱 실행 직후 강제 interstitial

interstitial은 초기에는 넣지 않는다. 나중에 도입하더라도 자연스러운 화면 전환에서만 낮은 빈도 cap으로 운영한다. rewarded 광고는 핵심 건강·기록 권한을 돈이나 광고 시청으로 바꾸는 구조가 되지 않도록 초기 범위에서 제외한다.

커뮤니티는 사용자 생성 콘텐츠를 포함하므로, 신고·숨김·정책 위반 콘텐츠 주변에 광고가 붙지 않도록 moderation read-path와 광고 슬롯을 분리해야 한다.

## 구현 순서 권장

1. 무료 핵심 기능을 유지한 채 30일 사용자 행동 계측을 먼저 확보한다.
2. Plus 혜택 2~3개와 가격/체험 기간을 PO 승인한다.
3. 서버 entitlement projection과 Play 구매 검증을 additive로 구현한다.
4. 테스트 트랙에서 구매·갱신·취소·환불·복구를 검증한다.
5. 광고는 동의·테스트 광고·정책·app-ads.txt를 먼저 닫고, 커뮤니티 목록 한 곳에만 제한적으로 시작한다.
6. 유료 구독자는 광고를 제거하고, 광고 도입 전후의 7일 유지율과 불편 신고를 비교한다.

## 현재 판단

지금 NURI는 기능 closeout 상태이지만, 결제 상품과 광고를 바로 넣을 단계는 아니다. 월 3,300원은 초기 실험 가격으로는 타당하나, `한 달 무료 후 전체 유료`는 추천하지 않는다. 무료 핵심을 남기고 Plus의 반복 가치를 증명하는 것이 이탈과 운영 리스크를 함께 줄이는 선택이다.
