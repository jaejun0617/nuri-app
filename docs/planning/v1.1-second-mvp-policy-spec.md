# NURI V1.1 2차 MVP 정책 확정서

기준일: 2026-07-01

## 0. 문서 목적

이 문서는 V1.1 추가 업데이트 2차 MVP의 구현 기준 v1이다.

대상은 데일리 streak/데일리판, 앱 내부 알림 read path, XP/레벨/칭호 최소 MVP다. 운영자 발송 UI, push notification, 홈 위젯, 무지개다리 추억 서비스, 고급 랭킹/뱃지는 이 문서의 구현 범위가 아니다.

## 1. 고정 QA 계정 정책

- 반복 QA 계정 표시명은 `adminQA`로 고정한다.
- `adminQA`는 이름만 adminQA이며 권한은 일반 사용자다.
- `adminQA`에 admin/super_admin 권한을 부여하지 않는다.
- 테스트 pet은 `AdminQAPet`을 사용한다.
- 테스트 데이터 prefix는 `ADMIN_QA_TEST`, `ADMIN_QA_NOTICE`, `ADMIN_QA_XP`를 사용한다.
- 보고서에는 비밀번호, token, provider 계정 전체값, 이메일 전체값을 노출하지 않는다.
- 무작위 신규 QA 계정은 생성하지 않는다.

## 2. 데일리 Streak / 데일리판 정책 v1

| 항목 | 확정 기준 |
|---|---|
| 시간대 | KST |
| 하루 기준 | KST 00:00부터 23:59까지 |
| 단위 | user + pet |
| 인정 조건 | 산책 카테고리 타임라인 게시글 작성 성공. 산책 장소 기록 경로는 후속 연결 후보 |
| 하루 인정 횟수 | user + pet + date 기준 1회 |
| 같은 날 여러 번 작성 | streak는 증가하지 않고 오늘 완료 상태만 유지 |
| 증가 조건 | 마지막 완료일이 어제면 current streak +1 |
| reset 조건 | 마지막 완료일과 오늘 사이에 하루 이상 공백이 있으면 1부터 다시 시작 |
| best streak | current streak가 best보다 크면 갱신 |
| 오늘 완료 여부 | 서버 summary 기준으로 조회 |
| 축하 모달 | 같은 날 첫 산책 인정 이벤트에 한해 앱에서 1회 표시 |
| 삭제/수정 정책 | 당일 산책 글 삭제 또는 카테고리 변경 시 source id 기준 activity를 제거하고 오늘 상태를 재계산 |
| 과거 기록 수정 | MVP에서는 future policy로 문서화 |
| 계산 위치 | client-only 계산 금지, Supabase RPC와 ledger 기준 |

## 3. 알림 Read Path 정책 v1

| 항목 | 확정 기준 |
|---|---|
| 앱 내부 badge | 전체메뉴 알림함 entry에 unread dot/count를 표시 |
| 알림 목록 | `UserNotifications` 화면에서 사용자 알림과 활성 공지를 read path로 제공 |
| 읽음 처리 | 단건 mark read를 제공하고 unread count를 갱신 |
| 숨김/삭제 처리 | 사용자가 알림 하나를 옆으로 충분히 밀면 카드가 이동한 뒤 목록에서 숨긴다. 알림별 X는 두지 않고 전체삭제만 같은 user-scoped dismiss 계약을 사용한다 |
| 펼침/접힘 | 카드는 접힘 상태에서 제목 1줄, 본문 최대 2줄, 날짜 하단을 표시한다. 화살표 indicator tap 또는 아래/위 스와이프로 expanded/collapsed 상태를 전환한다 |
| 특정 사용자 알림 | `user_notifications.user_id = auth.uid()` 기준 |
| 공지 알림 | active announcement read path는 준비하되 발송 UI는 앱 내부에 열지 않음 |
| empty state | 알림이 없으면 따뜻한 빈 상태 문구 표시 |
| push notification | MVP 제외 |
| 운영자 발송 UI | 별도 홈페이지/관리 페이지 트랙 |
| 권한 | 일반 사용자는 자기 알림과 활성 공지만 조회 |

## 5. DB/RPC/RLS 구현 기준

- 모든 핵심 상태는 Supabase ledger/summary/RPC 기준으로 저장한다.
- 직접 public projection은 만들지 않는다.
- anon 직접 접근은 열지 않는다.
- authenticated 사용자는 자기 데이터만 select할 수 있다.
- insert/update는 user-facing RPC 또는 trusted path로 제한한다.
- source event unique key로 중복 지급을 막는다.
- RLS negative smoke는 anon direct select 0건, 비로그인 RPC `42501` 계열 거부를 기준으로 한다.

## 6. 앱 구현 기준

- 데일리판과 XP 요약은 타임라인 인접 카드에 표시한다.
- 알림 read path는 전체메뉴 알림함 entry, `UserNotifications` 화면, 홈 상단 알림 아이콘의 floating notification shade로 제공한다.
- 홈 상단 알림 아이콘은 `오늘의 메시지로 하루를 시작해요` 문구 아래 위치에 상단 overlay shade를 연다. 이 shade는 홈 레이아웃 flow에 들어가지 않으며 홈 콘텐츠와 하단 네비게이션을 밀지 않는다. 목록/읽지 않은 알림 수/항목 읽음 처리/패널 X 닫기/backdrop tap 닫기/Android back 닫기를 제공하고, push나 운영자 발송 UI는 열지 않는다.
- 홈 알림 카드는 dark rounded shade 스타일로 표시한다. 알림별 X는 제거하고, 제목 1줄/본문 최대 2줄/날짜 하단/화살표-only indicator 구조를 사용한다. 좌우 스와이프는 카드가 손가락 방향으로 이동한 뒤 user-scoped dismiss를 호출하고, 아래/위 스와이프 또는 화살표 tap은 카드 펼침/접힘을 처리한다.
- 운영자 발송, push, marketing segmentation은 구현하지 않는다.
- 키보드바 QA는 로그인, 타임라인 작성/수정, 회원탈퇴 입력 모달, 알림 화면에 입력이 생길 경우 모두 포함한다.

## 9. 2026-07-02 V1.1 Final Sign-off 보안/범위 기준

판정: `V1.1 추가 업데이트 2차 MVP final sign-off 가능`

- Notification: 홈 상단 shade, 전체메뉴 알림함, unread count, 목록, mark read, user-scoped swipe dismiss, `전체삭제`, collapsed/expanded UX가 V1.1 범위다. 알림별 작은 X는 최신 UX 정리 결과 제거됐고, 주요 삭제 UX는 좌우 swipe dismiss와 `전체삭제`로 유지한다.
- Daily streak: KST user+pet+date ledger/RPC 기준을 유지한다. 같은 날 중복, KST 다음날, missed day, 삭제/카테고리 변경 재계산은 focused test/rollback smoke 기준으로 닫혔다.
- XP/level/title: source idempotency, daily cap, Lv.1~10, title 1회 지급을 유지한다. 삭제/신고/차단 콘텐츠 XP clawback, 고급 ranking, badge economy는 V1.1.1 후속이다.
- RLS/RPC: private tables anon direct select는 row 0, user RPC anon 호출은 `42501`, authenticated own-data only를 기준으로 한다. public projection은 walk/hospital의 기존 public-safe 계약만 허용한다.
- V1.1.1 scope audit: push remote notification, 운영자 발송 UI, 홈 위젯, 무지개다리 서비스, 고급 XP/랭킹은 V1.1 release scope에서 제외한다.
- 홈 위젯 scope gate: Android 홈 위젯 native/JS 일부 코드가 확인됐으나 V1.1 release 기능이 아니므로 release manifest receiver를 disabled/exported false로 막고 native package 등록을 제거했다. 후속 V1.1.1에서 정책/UX/QA를 재확정하기 전까지 사용자 노출은 금지한다.

## 10. V1.1.1 활동·칭호 대시보드 연결

V1.1.1 1순위는 `고급 XP/칭호/훈장/활동내역 대시보드`로 확정했다. 상세 정책 source of truth는 `docs/planning/v1.1.1-priority-and-activity-title-spec.md`다.

- 구현 위치: `전체메뉴 > 나의 반려동물 > 활동·칭호`
- 재사용 계약: `user_xp_ledger`, `user_level_summaries`, `user_titles`, `pet_streak_summaries`, 기존 XP/RLS/RPC
- 레벨 범위: 현재 서버 제약상 Lv.1~10 유지. Lv.11~30은 check constraint/function/RPC 검증이 필요한 Phase 2
- user/pet 분리: pet_id가 있는 활동은 펫별 카드, 커뮤니티 글/댓글은 `pet_id=null` 공통 활동
- 추가 연결: 건강 기록은 `health_record`, 커뮤니티 글은 `community_post`, 댓글은 `comment` XP 후처리로 연결
- 제외: push, 운영자 발송 UI, 홈 위젯, 무지개다리, ranking/leaderboard
