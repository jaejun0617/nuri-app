# NURI 전체 칭호 이름과 획득 조건 통합 설계안

작성일: 2026년 10월 22일

현재 상태: 2026-10-24 PO가 승인 이미지 332종의 앱 적용과 전체 획득 기능 구현을 명시 승인했다. 아래 본문의 미구현·향후 계약 표기는 2026-10-22 설계 당시 상태다. 실제 구현·원격 반영·기기 검증 상태는 `docs/qa/nuri-title-catalog-v2-integration-2026-10-24.md`에서 별도로 관리한다.

## 1. 전체 규모와 이번 개정

전체 칭호는 **332종**이다. 일반 308종과 히든 24종으로 구성한다. 일반에는 추억으로 함께하기 20종이 포함된다. 기존 제안과 달리 이 문서에는 332종 각각의 이름과 획득 조건을 빠짐없이 작성했다.

앞서 제시한 304종은 분야당 20종이라는 규모 제안이었다. 여기에 기억 관련 20종을 통합하고, 함께 기록한 시간에 중간 기념 8종을 추가해 332종으로 정리했다. 이는 제품에 구현된 칭호 수가 아니라 이번 설계안의 실제 목록 수다.

이름은 기존 칭호의 역할과 성취감을 유지하면서 다정하고 귀엽게 다듬었다. 장난스러운 의성어 별명이나 같은 접미사의 반복은 피한다. 일반 조건은 첫 제안보다 낮추고 초반과 중간 목표를 촘촘하게 추가했다. 히든 24종은 이름만 개정하며 기존 제안의 조건과 판정 규칙을 유지한다.

## 2. 전체 조건을 읽는 방법

### 2.1. 칭호 번호와 레벨

표의 번호는 새 설계 버전의 항목을 구분하기 위한 식별자다. 현재 제품 ID나 이전 제안의 같은 번호와 자동으로 동일시하지 않는다. 실제 적용 시에는 기존 ID와 아래 매핑을 명시적으로 연결한다.

번호가 앞선 칭호를 전부 얻어야 다음 칭호가 열리는 구조가 아니다. 각 행의 조건을 충족하면 독립적으로 획득한다. 예를 들어 GPS를 쓰지 않아도 시간과 추억, 계절, 기억 분야를 계속 진행할 수 있다.

기존 계정 XP 레벨과 Pet별 GPS Walk Level은 유지한다. LV 분야만 계정 XP 레벨을 조건으로 쓴다. 다른 분야의 번호를 XP 레벨로 표시하지 않는다. 칭호 획득 자체에 새 XP를 지급하지 않는다.

### 2.2. 일반 기록의 적격성과 하루 집계

적격 기록은 소유권과 실제 서버 저장이 확인된 기록이다. 초안, QA fixture, 임시 시험 세션, 중복 원본, 삭제 상태, 운영상 무효 자료는 새 진도에서 제외한다. 미확정 오프라인 결과는 획득 완료로 승격하지 않는다.

WK, MR, FD, PH의 '기록 N일'은 서로 다른 KST 기록 날짜 N개다. 같은 아이의 같은 분야는 하루에 여러 기록을 만들어도 하루만 센다. 수정, 재시도, 삭제 후 같은 원본 재작성으로 횟수를 늘리지 않는다. 같은 GPS Session과 그 Session의 Memory를 산책 분야에서 두 번 세지 않는다.

같은 기록이 추억 분야와 루틴처럼 다른 조건에 기여하는 것은 허용한다. 이는 하나의 보상을 여러 번 지급하는 것과 다르며 칭호로 인한 추가 XP는 없다. 기록 분류는 기존 내부 코드로 판정하고 본문 단어로 추측하지 않는다.

기록 날짜는 기존 서비스 정책을 따른다. 과거 추억을 올릴 수 있지만 과거 사진의 촬영일이나 사용자가 입력한 날짜만으로 실제 앱 사용 기간과 여러 해의 명절 참여가 생기지는 않는다.

### 2.3. 완화한 일반 주간과 월간 조건

| 지표 | 이번 일반 조건 |
| --- | --- |
| 기록한 날 | 해당 아이의 산책, 식사, 건강, 생활 돌봄, 일기 중 적격 기록이 하나 이상 있는 날짜 |
| 기록한 주 | KST 월요일부터 일요일 사이 서로 다른 2일 이상 기록한 주 |
| 루틴 월 | 한 달에 서로 다른 6일 이상, 서로 다른 2개 주에 걸쳐 기록한 달력 월 |
| 균형 월 | 서로 다른 2분야에서 각 2일 이상 기록하고, 전체 기록 날짜가 4일 이상인 달력 월 |
| 건강 관찰 주 | 건강 관찰, 체중 또는 기존 의료 기록 중 하나가 있는 달력 주. 같은 주는 최대 1개 |
| 생활 돌봄 월 | 기존 목욕/위생 또는 미용에 구조화 관리 항목이 있는 기록이 존재하는 달력 월. 같은 월은 최대 1개 |
| 기록한 계절 | 실제 계절 안에 적격 기록이 서로 다른 1일 이상 있는 연도별 계절 |

균형 월의 분야는 산책, 식사, 건강, 생활 돌봄, 일기 다섯 종류다. 같은 기록의 사진과 본문을 서로 다른 분야로 나눠 세지 않는다. 실제로 2분야를 쓸 필요는 있지만 모든 분야나 의료 행위를 요구하지 않는다. 같은 날짜에 두 분야를 기록했다면 각 분야에는 반영하되 전체 기록 날짜는 하루다.

달력 월과 주는 연속일 과제가 아니다. 쉰 달이 있어도 이전에 쌓은 월과 주는 유지한다. 기록한 달 수는 매달 빠짐없이 돌봤다는 인증이나 실제 경과 연수와 같지 않다. 진도 단위를 생략하지 않는다.

이 완화는 일반 칭호에만 적용한다. 히든의 3일, 3분야, 기간 길이와 지연 수신 조건을 위 표로 바꾸지 않는다.

### 2.4. 시간과 계절의 기준

실제 기록 기간은 해당 아이에 대해 검증 가능한 최초 서버 기록 시점부터 계산한다. 생일, 만난 날짜, 이별 날짜, 사진 촬영일로 대체하지 않는다. 기존 홈의 함께한 시간 계산값을 덮어쓰지 않는다.

개월과 연수는 KST 달력 기념일을 사용한다. 해당 월에 같은 일이 없으면 말일을 사용하고, 2월 29일의 평년 기념일은 2월 28일로 처리하는 안이다. 실제 기간 조건이 있는 칭호는 해당 기념일 이후 다음 적격 기록을 남길 때 판정한다.

계절은 봄 3월부터 5월, 여름 6월부터 8월, 가을 9월부터 11월, 겨울 12월부터 다음 해 2월이다. 겨울은 12월이 속한 연도로 식별한다. 테마 미리보기와 수동 계절 전환은 조건에 영향을 주지 않는다.

15년이나 20년이라는 기념 자체를 짧게 위조하지는 않는다. 대신 필요한 기록량을 낮추고 그 사이의 기념을 추가한다. 기존 계정 Lv.100 기준도 변경하지 않고 중간 레벨 칭호를 늘린다.

### 2.5. 지켜야 할 경계

이 칭호는 앱에 남긴 성취를 격려하는 목표이지 보호자 자격이나 실제 돌봄의 질, 건강 상태를 인증하는 점수가 아니다. 병원, 투약, 목욕, 미용 횟수와 지출액을 늘리도록 보상하지 않는다. 악천후, 야간, 속도 경쟁, 쉬지 않는 산책도 조건으로 만들지 않는다.

기존에 얻은 칭호는 조건 개정으로 회수하지 않는다. 일상적인 휴식과 일반 기록 삭제 때문에 역사적 성취를 자동 회수하지 않는 방향을 유지한다. 현재 GPS 평생 거리와 Walk Level은 기존 Session 삭제 정책에 따라 별도로 재계산한다. 사기와 운영 무효에 대한 취소는 별도의 근거 있는 서버 절차로 다루며 계정과 아이의 최종 삭제 계약은 지킨다.

## 17. 추억으로 함께하기 20종

무지개다리를 건넌 아이도 과거 사진을 올리고 지금의 추억을 남기며 이야기를 이어갈 수 있어야 한다. 이 분기는 이별한 지 얼마나 지났는지나 슬픔의 크기를 평가하지 않는다. 개인 기록은 비공개여도 되고 사진이 필수가 아닌 길도 있다.

현재 source의 추모 상태와 별도로 기억 활동 참여를 사용자 선택으로 설계한다. 칭호를 위해 새로운 이별 날짜 입력이나 추모 프로필 변경을 강제하지 않는다. 그 최소 참여 상태와 기록 연결은 향후 구현 계약이며 이번에 이미 구현된 기능이라고 보지 않는다.

### 18.5. 히든의 기존 판정 규칙 보존

모든 기간은 KST 날짜의 시작을 포함하고 마지막 날 다음 날 00시를 제외한다. 설날, 정월대보름, 추석은 연도별 별개 기준일이다. 검증된 공식 달력 자료를 서버에서 보관하는 방향을 유지하고, 미확정 연도는 임의 날짜로 지급하지 않는다. [한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do)와 [음양력 변환](https://astro.kasi.re.kr/life/pageView/8)을 기준 자료로 삼는다.

명절과 기념일 참여를 여러 해 쌓으려면 당시의 저장 증거가 필요하다. 신규 기록은 행사 기간 안의 실제 기록 날짜와 기간 종료 후 7일 이내 서버 수신을 함께 충족해야 한다. 오프라인 기록에도 같은 여유 기간을 적용한다. 시스템 장애가 7일을 넘기면 근거 있는 별도 보정 검토 대상으로 두고 가짜 참여나 자동 실패로 처리하지 않는다.

기존 과거 이력은 당시의 서버 저장 시각 등 검증 가능한 자료가 있을 때만 소급 인정한다. 오늘 입력한 과거 날짜 기록이나 기기 시계 변경만으로 과거 여러 해의 참여가 생기지 않는다. 조건과 별개로 아직 해당 연도의 공식 달력을 수집하거나 앱에 연결한 것은 아니다.

생일과 만난 날짜는 개인 프로필에 따른 기념일이지 외부 검증된 나이 인증이 아니다. 현재 아이의 추모 상태를 외부로 공개하거나 이별 날짜를 히든 조건으로 추가하지 않는다. 명절을 놓쳐도 다음 해 기회가 있으며 유료 재도전과 스트릭 복구 아이템은 없다.

| 히든 | 24개 조건 | 조건과 기간 유지, 이름만 변경 |

보관함은 번호상 다음 하나만 추천하지 않는다. 현재 진도와 사용 분야에서 가까운 일반 목표 최대 3개를 추천하고 사용자가 즐겨찾는 목표 최대 3개를 별도로 둘 수 있다. 동일 목표는 중복 표시하지 않는다. 멀리 있는 15년 기념이 지금 달성 가능한 사진이나 기록 목표를 밀어내지 않게 한다.

이 목록을 소진할 속도는 사용자마다 다르다. 활동량만 큰 사용자는 일부 분야를 빨리 끝낼 수 있지만 계절과 실제 시간, 루틴과 기념일은 별도로 남는다. 반대로 낮은 빈도로 쓰는 사용자도 가까운 기록 목표와 해마다의 기념을 얻을 수 있다. 칭호 달성 속도를 위해 기록을 남발하도록 권하지 않는다.

## 21. 추모 사용자와 개인 선택 보호

누리처럼 추모 아이의 사진과 추억을 정리하는 사용자는 산책과 식사 진도를 더 쌓지 않아도 MR, PH, SE, TM, ME와 공통 활동을 이어갈 수 있다. 기존 산책 성취는 보관하고 새로 할 수 없는 과제를 상단에 권유하지 않는다.

개인 기록의 원본 날짜와 지금 추억을 남긴 저장 시각을 구분한다. 예전 사진을 올렸다고 사진 촬영 후 15년을 앱 사용 15년으로 계산하지 않는다. 기존 사진을 많이 정리하는 날에는 ME의 원본 수 목표가 가능하고, 지속해서 기록한 날은 PH와 루틴 등에 별도로 기여한다.

기억 분기를 열거나 홈 대표 칭호를 선택해도 추모 상태와 이별 날짜가 커뮤니티에 자동 공개되지 않는다. 다른 아이를 등록해도 이전 아이의 성취를 없애거나 새 아이에게 복사하지 않는다. 새 참여 동의와 기존 추모 표시의 관계는 구현 전에 최소 계약으로 확정한다.

'잊고 있어요', '사진을 더 올려야 해요', '기일이 다가오니 참여하세요', '이별 극복' 같은 압박이나 평가 표현은 제외한다. 사용자 작성 후 조용한 안내를 기본으로 하고 강한 축하 팝업과 자동 알림을 강제하지 않는다. 숨기기와 목표 추천 해제가 가능해야 한다.

## 22. 이미지와 구현의 분리

최종 승인된 칭호마다 서로 다른 전용 원본을 배정한다. 이 설계가 그대로 승인되면 332개 전용 이미지 항목이 필요하다. 같은 그림의 복사, 색 변경, 숫자 변경만으로 다른 칭호를 완성하지 않는다. 질감, 광원, 제품 톤은 통일하되 주 피사체, 구도, 소품과 실루엣으로 각 성취를 구별한다.

이번에는 이미지를 제작하지 않는다. 이미지가 없는 항목은 제작 대기이며 다른 칭호 그림으로 임시 완성 처리하지 않는다. 작은 홈 표시 크기에서도 식별되는지, 긴 이름은 실제 텍스트로 읽히는지 향후 확인한다.

canonical catalog, 서버 소유 범위, 기존 성취 보존, 진도 집계, 대표 칭호 동기화와 정책 버전은 구현 전 별도 계약이 필요하다. 현재 앱과 원격 서버에 332종이 등록되었다고 보고하지 않는다. 기존 XP, GPS 엔진, 타이머, DB/RPC/RLS와 삭제 정책을 이번 문서만으로 변경하지 않는다.

## 23. 목록 정합성 확인 기준

전체 표에는 WK, GD, MR, FD, HC, LC, RT, BL, PH, SE, CP, CM, LV, ME가 각각 20종, TM이 28종, X가 24종 있어야 한다. 식별자와 새 이름은 전체 332종에서 각각 중복이 없어야 한다. 각 행에는 단위가 있는 실제 조건을 적고 '추후 결정'으로 조건을 비워 두지 않는다.

히든은 X01부터 X24까지 최초 제안의 조건 문장을 그대로 대조한다. 일반 완화가 히든 해석에 전파되지 않았는지도 확인한다. 명절, 생일, 만난 날, 돌아오기, 계절 경계, 3분야 조건은 각각 분리한다.

기존 18종은 하나씩 매핑되어야 한다. ME11부터 ME15의 계정 공통 5종을 아이별 15종과 합쳐 20종으로 한 번만 센다. 일반 308종 중 아이별 243종과 계정 공통 65종, 여기에 아이별 히든 24종을 더해 332종인지 대조한다.

이 확인은 문서의 목록과 조건 정합성 검사이며 앱 테스트, 실기기 검증, 실제 보상 지급 확인이 아니다.

문서 점검 결과: 전체 332행, 이름과 식별자 각각 332개 중복 없음, 일반 308종, 히든 24종, 기존 18종 매핑 모두 존재함을 확인했다. 히든 24개 획득 조건 문장은 최초 보고서와 항목별로 일치했다. 새 이름의 최대 길이는 공백 포함 12자이며 실제 폰트 렌더링 검증은 아직 수행하지 않았다.
