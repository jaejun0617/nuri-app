# 알림 v3 이벤트 계약

상태: 로컬 구현 및 계약 검증. 원격 반영·기기 증적은 최종 QA 문서에서 별도 판정한다. Master 단독 작업이며 기존 XP·칭호·moderation·일정 로컬 예약 정책은 변경하지 않는다.

최신 추가 보정: `20261025094515` 이후 기념일 설정은 anniversary, 추모는 memorial만 확인하며 record와 중복 gate하지 않는다. `20261025091403`의 service는 다른 category의 master가 아니다. `20261025095926`은 기존 owner RLS 아래 preferences Realtime publication만 연결한다. 아래 초기 registry의 record+anniversary/record+memorial 표기는 이 변경 이력이며 현재 실효 설정은 이 문단과 실제 함수 기준이다. 원격 반영·단말 수락은 [통합 원장](../qa/nuri-integrated-closeout-2026-10-25.md)을 따른다.

## 공통 규칙

- 모든 신규 이벤트는 schemaVersion=1. 업무 트랜잭션의 확정 INSERT 또는 UPDATE/DELETE 트리거에서 기존 user_notifications와 private delivery outbox를 함께 기록한다. 외부 HTTP는 이 트랜잭션에서 실행하지 않는다.
- 수신자별 dedupe_key unique, 원본 종류·ID·버전으로 이벤트를 식별한다. 자기 댓글·답글·좋아요는 제외하며 양방향 차단·삭제 요청 중인 계정을 제외한다. 원본 접근 권한은 조회·클릭·발송 직전에 다시 확인한다.
- 인앱 알림함은 OS 푸시 거부 상태에서도 유지한다. push_opt_in과 아래 채널 설정이 모두 허용될 때만 OS 발송한다. 기존 OFF 설정은 병합 시 보존한다. 설정의 기본 미지정 값은 OFF다.
- read_at은 정상적으로 상세 화면이 열린 후 서버에 저장한다. 목록 노출은 읽음이 아니다. 모두 읽음은 한 MVCC snapshot에 materialize한 대상만 처리한다. available_at + ID + source 커서와 동일 서버 전체 미읽음 집계를 사용한다.
- 모든 target은 허용된 유니온만 해석한다. 원본 삭제·권한 상실 시 안내와 읽음 정리를 허용하며 임의 내부 라우트나 URL은 실행하지 않는다. 계정 전환 시 캐시·구독·대기 탭을 폐기한다.
- UTC 저장, 사용자 IANA time_zone 사용, 미설정은 Asia/Seoul. period CTA의 endDate는 exclusive다.

## 발송과 외부 설정

- SQL scheduler와 공지 fanout은 분당 최대 100 사용자 배치, cursor/advisory lock 및 dedupe를 사용한다. activation 이전 요약·공지를 일괄 재발송하지 않는다.
- Worker는 4건/회 lease, 기기별 영수증으로 재시도 중 이미 접수된 기기를 제외한다. transient만 최대 5회, 지수 backoff 30초~1시간, TTL 24시간. 무효 토큰은 폐기하며 401/403 등 provider unavailable은 시도 횟수를 소비하지 않고 1시간 대기한다.
- 활동·커뮤니티·회고는 2분 bucket으로 OS 알림을 묶는다. 인앱 개별 이벤트는 보존한다. 전경에서는 OS 배너를 중복 표시하지 않고 목록을 invalidate한다. FCM 접수는 단말 표시나 사용자 열람 성공이 아니다.
- 필요한 Edge secrets: NURI_FCM_SERVICE_ACCOUNT, NURI_PUSH_TOKEN_KEY(base64 32bytes), NURI_NOTIFICATION_WORKER_SECRET. Vault의 nuri_notification_worker_secret도 동일 worker credential이어야 한다. 미설정 시 토큰 획득·등록 및 HTTP cron을 fail closed한다. 앱에 service role·암호화 키·FCM 키를 넣지 않는다.
- 기기 토큰은 서버에서 AES-256-GCM 암호화, owner+device AAD를 사용한다. 다중 기기별 관리, 계정 교체 시 이전 owner binding 폐기, 로그아웃 시 device scoped revoke. 화면 방문 때 OS 권한 팝업을 요청하지 않는다.

## 검증 경계

로컬 SQL 계약은 중복·권한·달력 경계·읽음 범위·발송 lease·설정 변경·일정 무효화를 검증한다. transport 계약은 암호화·AAD·오류 분류·본문 상한을 검증한다. 실제 FCM 키가 없는 전경/백그라운드/종료 푸시 표시는 NOT_VERIFIED다. 실제 사용자 알림을 visual fixture로 쓰거나 삭제·읽음 변경하지 않는다.

## 관리 및 전달 경계

- 기존 개별·전체 삭제 기능은 행 길게 누르기와 접근성 관리 동작으로 유지한다. 관리 메뉴 뒤 별도의 삭제 확인을 요구하며 상세 열기·읽음 처리는 삭제하지 않는다. 서버의 기존 삭제 RPC는 v3 가시 범위 snapshot과 공지 publish_version에 맞춰 soft-dismiss한다. 재발행·미래 알림·다른 계정에는 적용하지 않는다.
- OS 구현 범위는 Android FCM 후보이며 iOS APNS 완료를 의미하지 않는다. priority는 기존 normal 기본값을 유지하고 일정의 OS 알림은 기존 Native 로컬 예약이 소유한다. 임의 긴급 발송 정책을 추가하지 않는다.
- 구현·원격 반영·실기기 검증은 [전달 기록](../qa/nuri-notifications-delivery-2026-10-25.md)에서 분리한다. 이벤트별 운영 E2E 전체 PASS가 아니며 푸시 외부 설정과 실제 다중 기기·인증 복귀 matrix는 미검증이다.
