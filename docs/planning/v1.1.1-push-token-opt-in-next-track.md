# V1.1.1 Push Token / Opt-in 다음 트랙

## 2026-07-19 현재 계약

- opt-in/out, Android permission, user/device scoped register, logout revoke 및 controlled account switch isolation을 완료했다.
- `adminQA`, controlled Google/Kakao QA identities의 최종 non-revoked binding은 0이고 cross-user active device도 0이다.
- 실제 OS token rotation은 발생하지 않았으며 refresh handler의 동일-device upsert·ownership·stale replacement는 focused test/RPC evidence로 고정했다.
- actual push provider, broadcast, segment dispatcher는 계속 비활성이다. 이 문서는 actual push 착수 지시가 아니며 PO 승인 전 활성화하지 않는다.

기준일: 2026-07-11

## 목적

운영자 알림 관리 콘솔과 앱 내부 알림 row 생성은 1차로 닫혔지만, 실제 원격 push notification은 아직 구현하지 않는다. 이 문서는 다음 트랙에서 push token 저장, 권한 UX, opt-in/out, 발송 queue를 열기 위한 선행 조건과 release gate를 고정한다.

## 범위

- 이번 문서화 턴에서는 실제 push 발송, FCM/Expo secret 사용, permission prompt 노출, token table migration을 구현하지 않는다.
- 다음 구현 턴에서는 사용자 동의, token lifecycle, 운영자 콘솔 연동, failure log를 먼저 닫은 뒤 원격 push 발송을 제한적으로 연다.

| 항목 | 정책 | 구현 필요 여부 | 위험도 | 선행 조건 |
|---|---|---|---|---|
| Push permission UX | 앱 첫 실행에서 즉시 묻지 않고, 알림 가치가 설명되는 화면에서 명시 opt-in으로 요청 | 예 | 중간 | 문구/디자인 확정, Android permission version 확인 |

| Token refresh | 앱 시작/권한 변경/FCM refresh 시 upsert. 중복 token 정규화 | 예 | 중간 | Firebase/Expo 선택, native handler |
