# V1.1.1 우선순위 및 활동·칭호 대시보드 정책 v1

최신 기준일: 2026-07-03

이 문서는 V1.1 final sign-off 이후 V1.1.1 후보 기능의 우선순위와 1순위 구현 범위를 고정한다.
이번 턴의 구현 대상은 `고급 XP/칭호/훈장/활동내역 대시보드 1차 MVP`이며, ranking/leaderboard는 privacy/RLS 설계가 필요하므로 제외한다.

## 2. 기존 XP/level/title 구조 분석

현재 구현된 서버 계약은 V1.1 2차 MVP 기준이다.

| 항목 | 현재 상태 |
| --- | --- |
| XP ledger | `user_xp_ledger`, `user_id`, optional `pet_id`, `event_type`, `source_type`, `source_id`, `xp`, KST date, unique source key |
| level summary | `user_level_summaries`, user-level total XP, `level between 1 and 10` |
| title storage | `user_titles`, user-level unique `title_key`, optional `pet_id`는 존재하지만 unique key는 user+title 기준 |
| XP award RPC | `award_user_activity_xp_v1`, source idempotency, daily cap, base activity cap |
| summary RPC | `get_user_level_summary_v1`, `get_user_titles_v1` |
| daily streak | `pet_daily_activities`, `pet_streak_summaries`, `get_pet_daily_status_v1` |
| 현재 실제 연결 | 산책 타임라인, 일반 타임라인, 건강 기록, 커뮤니티 글, 댓글 |
| user/pet isolation | RLS 기준 자기 row만 select. dashboard도 cross-user/ranking query 없음 |

레벨은 현재 서버 제약과 RPC가 Lv.1~10으로 고정되어 있다. Lv.11~30 확장은 table check constraint, level calculation function, next/floor XP function, focused RLS/RPC test가 함께 필요한 Phase 2 작업이다. 이번 턴에서는 DB migration 없이 Lv.1~10 계약을 유지한다.

## 3. XP 지급 이벤트 정책

이번 턴에서 유지하거나 연결한 event type은 아래와 같다.

| 이벤트 | XP | daily limit | scope | 실제 연결 상태 |
| --- | ---: | ---: | --- | --- |
| 산책 기록 | 20 | 2 | pet | 정책/RPC 존재. 산책 장소 기록 경로 직접 연결은 후속 |
| 산책 타임라인 게시글 | 30 | 1 | pet | 연결 완료 |
| 일반 타임라인 게시글 | 15 | 3 | pet | 연결 완료 |
| 건강 기록 | 10 | 2 | pet | 건강 카테고리 기록 작성 시 `health_record`로 연결 |
| 커뮤니티 글 | 10 | 2 | user common | 작성 성공 후 user-level 후처리로 연결 |
| 댓글 | 3 | 10 | user common | 댓글 작성 성공 후 user-level 후처리로 연결 |
| 3/7/30일 streak bonus | 30/80/300 | 1 | pet/user event | 정책/RPC event type 존재. bonus 자동 지급 고도화는 후속 |

XP 지급 실패는 원본 작성 flow를 막지 않는다. 서버 RPC의 idempotency와 daily cap이 source of truth이며, 앱은 후처리 실패를 사용자 작성 실패로 전파하지 않는다.

## 4. 멀티펫 분리 정책

pet-scoped 활동은 pet 단위로 분리한다.

- 산책 기록
- 산책 streak
- pet_id가 있는 타임라인 XP
- 건강 기록
- pet_id가 있는 XP ledger
- pet별 조건으로 계산한 칭호/훈장

user-scoped 공통 활동은 특정 펫 하나에 귀속하지 않는다.

- 커뮤니티 글
- 댓글
- pet_id 없는 XP ledger
- user-level 대표 칭호

커뮤니티 글/댓글 XP는 `pet_id=null`로 기록하며, 멀티펫 카드에 중복 합산하지 않는다. 기존 데이터에 pet_id가 없는 활동은 임의 pet에 매핑하지 않는다.

## 5. UI 구현 기준

구현 위치는 `전체메뉴 > 나의 반려동물 > 활동·칭호`다.

탭/섹션 명칭은 `활동·칭호`로 확정한다. XP, 레벨, 칭호, 훈장을 모두 포괄하면서 `나의 활동내역`보다 딱딱하지 않고 반려동물 앱 톤에 맞기 때문이다.

1차 MVP 카드:

- 현재 성장 카드: 현재 레벨, 총 XP, 다음 레벨까지 남은 XP, progress bar, 대표 칭호
- 아이별 성장 기록: 멀티펫 분리 선택 카드
- 펫별 활동 카드: 산책, 타임라인, 건강관리
- 타임라인 카테고리 카드: 기존 카테고리 count read path 재사용
- 공통 활동 카드: 커뮤니티 글, 댓글
- 칭호·훈장 보관함: 획득/미획득 조건 표시

디자인 톤은 premium pet diary/activity archive로 유지한다. 경쟁형 ranking, leaderboard, 과한 게임 UI는 제외한다.

## 6. 보안/RLS 원칙

- 대시보드는 기존 user-scoped RLS table과 authenticated RPC만 사용한다.
- cross-user ranking query는 없다.
- user-level 공통 활동과 pet-level 활동을 UI와 view model에서 분리한다.
- 커뮤니티 활동을 모든 펫에 중복 합산하지 않는다.
- raw/internal/admin field와 secret/token은 표시하지 않는다.
- 신규 migration/RPC는 이번 턴에서 생성하지 않았다.

### 알림 보존 정책

- 홈 floating 알림창의 좌우 swipe dismiss와 `모두 치우기`는 이제 홈 간편창에서만 숨기는 local/user-scoped 상태로 분리한다.
- 전체보기/알림함의 개별 삭제와 전체삭제는 기존 서버 RPC의 user-scoped hide를 유지한다.
- read, home quick dismiss, inbox delete는 서로 다른 상태로 취급한다.
- 홈에서 치운 알림은 전체보기/알림함에는 남아야 하고, 전체보기에서 삭제한 알림은 홈 간편창에도 다시 나오면 안 된다.
- close, backdrop close, Android back close는 삭제도 home dismiss도 아니다.
- 이번 셸에는 service role key가 없어 adminQA 새 알림 row를 직접 생성하지 못했다. live item retention smoke는 focused test와 기존 read path 증적으로 보완하고, 운영/관리 도구가 준비된 뒤 실제 알림 row evidence를 추가한다.

### 보안/RLS

- anon direct select는 user-scoped table에서 row 0 또는 42501로 닫혔다.
- anon RPC는 `get_user_notifications_v1`, `dismiss_user_notification_v1`, `dismiss_all_user_notifications_v1`, `get_user_titles_v1`, `award_user_activity_xp_v1`, `record_pet_daily_activity_v1` 모두 42501로 차단됐다.
- 신규 DB/RPC/migration 없이 기존 RLS와 user/pet isolation을 유지했다.

## 13. 2026-07-09 프리미엄 보상 모달 closeout

활동·칭호 대시보드의 성장 피드백을 보완하기 위해 XP/포인트 획득 순간에만 `PremiumRewardModal`을 표시한다. 서버 XP ledger, level summary, title, RLS/RPC 계약은 변경하지 않는다.

### 정책

- XP 또는 산책 streak 보상이 있는 작성 flow에서만 표시한다.
- XP 지급이 없는 단순 완료 flow는 `PremiumNoticeModal`을 사용한다.
- `오늘 하루 안 보기`는 KST 기준 user-scoped local preference다.
- 같은 날 다시 표시하지 않고, 다음 날에는 다시 표시될 수 있다.
- preference는 presentation-only 상태이며 XP ledger, activity dashboard, notification state와 섞지 않는다.
